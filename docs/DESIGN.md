# 設計の記録

README が使う人向けの入口、[マニュアル](MANUAL.md) が使い方、[開発の手引き](DEVELOPMENT.md) が構造とビルドを扱うのに対し、この文書は **いま従うべき規則の一覧** です。issue を 1 つ閉じても消えない種類のこと、つまり後から来た実装が従うべき制約と、同じ検討を二度しないための判断だけを置きます。

- **判断が変われば書き換えます。** 「なぜそうなったか」「何と迷ったか」は [設計判断の記録（ADR）](adr/README.md) にあり、そちらは書き換えません。経緯が要る規則には、行末に ADR へのリンクを付けてあります
- **進行中の作業は [GitHub issues](https://github.com/tokuhirom/ekanban/issues) で管理します。** 「次に何をやるか」はここには書きません
- **何ができるかは README に、モジュールの構成・スキーマ・ビルドは [開発の手引き](DEVELOPMENT.md) にあります。** 実装済みの機能の一覧をここには置きません。置くと、issue を閉じるたびに直す文書になります

## 引き継ぐ設計の決まりごと

今後の実装が従うもの。**足す・書き換える・破るときは ADR が要ります**（[ADR 0007](adr/0007-adr-required-for-significant-decisions.md)、判定は [`docs/adr/README.md` の「いつ書くか」](adr/README.md#いつ書くか)）。

### 層の分け方

- **どちらに書くかは、ウェブアプリとして作ったときにサーバ側へ書くだろうものかで決める。** そうでないものは webview に置く。Tauri の殻はこの見立てでは「ブラウザそのもの」で、ウェブアプリなら書かずに済んだはずのもの（窓、ネイティブのメニュー、OS のダイアログ、グローバルホットキー）だけが Rust に残る。打った文字の読み方も、一致の判定も、書き出す文字列の組み立ても、サーバには置かない（[ADR 0039](adr/0039-the-board-model-moves-to-typescript.md)）
- **書き出しは 2 つに分ける。** 人が読む Markdown は webview（`web/src/model/export.ts`）、置いてある形の写しである JSON は置き場所（`crates/core/src/export.rs`）。分かれ目は形式ではなく、**材料が置き場所にしか無いかどうか**——JSON には採番の続きのように、境界を越えて画面へ渡さない値が入る。ファイルに書くコマンド（`write_text_file`）は中身を見ない（[ADR 0045](adr/0045-two-kinds-of-export.md)）
- **置き場所は、受け取ったものを検めてから書く。** 盤面の判断をやり直すのではなく、整合だけを見る——空のタイトル、知らないカラムを指すカード、日付として成り立たない期限。どこに落とすかを決めるのは webview で、それが行として成り立つかを見るのが置き場所（[ADR 0040](adr/0040-the-shape-and-the-store-stay-in-rust.md)）
- **`crates/core`（`ekanban-core`）に UI ツールキットを依存させない。** `model.rs` / `db/mod.rs` / `backup.rs` / `paths.rs` / `instance.rs` / `diagnostics.rs` は画面の作りを知らない。これが、テストを GUI のランタイム無しで走らせ続ける条件であり、アプリと開発用のハーネスが同じコードを使える条件でもある。依存の依存から入り込むほうがありがちなので、解決した依存グラフを `script/check-core-independence` が CI で見る
- **`crates/app/src/commands.rs` に `tauri` を出さない。** `ipc.rs` の `#[tauri::command]` は、その関数を呼ぶだけの包み。判断を包みの側に置かないことは設計そのもので、開発用のハーネス（`crates/harness`）が同じ関数を HTTP に出せるのはこれによる
- **盤面の置き場所は差し替えられる。モデルは差し替えない。** `crates/core/src/store.rs` の `Store` が口で、配るアプリは SQLite（`db/mod.rs`、`sqlite` feature）、ブラウザ版は JSON（`store::JsonStore`）。**分かれているのは「どう置くか」だけ**で、採番も並べ替えも Undo も `model.rs` の 1 つのまま。`Store` に盤面の判断を書かない（[ADR 0036](adr/0036-one-model-two-places-to-put-it.md)）
- **`crates/app` の `shell` feature の外に、Tauri を出さない。** 窓・ネイティブのメニュー・OS のダイアログ・グローバルホットキーがその内側で、外に残るのは `commands` / `dispatch` / `state` / `snapshot` / `error` と、メニューの「データとしての構成」。ブラウザだけで動く版（`crates/web`）が、殻を外したこの層をそのまま使う（[ADR 0035](adr/0035-a-browser-build-of-the-real-core.md)）
- **コマンド名で振り分ける表を 2 つ持たない。** `crates/app/src/dispatch.rs` の 1 つを、開発用のハーネスとブラウザ版が通る。環境で答えが変わるもの（保存先を選ぶ、場所を開く、URL を開く）だけが呼ぶ側に残る
- **SQL は `crates/core/src/db/` に閉じる。** `tauri-plugin-sql` は使わない。スキーマ移行も差分保存もここにあり、それを捨てる理由がない。`tauri-plugin-store` も使わない——表示の状態は `app_state` テーブルにあり、データの置き場所を 2 つに割る理由がない

### 状態の持ち主

- **盤面は Rust が持ち、webview はその投影だけを描く。** 採番・並べ替え・Undo / Redo・アーカイブ・タグの論理は `model.rs` にあり、テストも付いている。同じものを TypeScript にもう 1 つ持つと、2 つの真実を突き合わせ続けることになる（[ADR 0018](adr/0018-rust-owns-the-board-state.md)）
- **確定していない入力は webview のもの。** タイトル、説明、タグ名、カラム名、検索語。IME の変換中を IPC 越しに往復させる意味がなく、`Escape` で捨てるだけのものを Rust に持たせる理由もない
- **無題のカードを作らない。** カードが足されるのはタイトルが入って確定した瞬間の 1 回だけで、それまで下書きは webview の中にある。取り下げられたカードは一度も存在しないので、`card_events` にも Undo にも残らない
- 置き場所の分け方はこう決まっている。

| 種類 | 置き場所 | 例 |
| --- | --- | --- |
| 盤面 | Rust（`AppState`） | カード、カラム、タグ、アーカイブ、Undo / Redo のスタック |
| 永続する表示の状態 | SQLite の `app_state`（Rust 経由） | 絞り込み、最後に開いたボード、テーマ、サイドバー、ウィンドウ矩形、キャプチャ先と割り当て |
| 一時的な表示の状態 | webview | 開いているパネル、選択中のカード、メニューの開閉、スクロール位置 |
| 下書き | webview | 入力欄の中身。確定するまで Rust に渡さない |

- **保存済みのカードは、欄ごとに確定する。** 編集パネルに「保存」は無く、欄を離れた時点で `update_card` を呼ぶ。タイトルと期限は `Enter` でも、チェックとタグは押した瞬間に、説明は欄を離れたときと打ち止まって 1 秒で確定する（打鍵のたびには確定しない。Undo が 1 文字ずつ積まれる）。確定は 1 本に並べ、送るのはそのときいちばん新しい下書き。**新しいカードだけは下書きのまま**で、足す 1 回の操作が要る（[ADR 0032](adr/0032-committing-a-card-field-by-field.md)）

### コマンドとイベント

- **1 つのコマンドが 1 つのモデル操作を呼び、保存し、変更後のスナップショットを丸ごと返す。** 差分は返さない。適用の順序と欠落を webview 側で面倒みることになり、そこは作りたくない部分だから。数百枚のカードで数百 KB、操作は「1 回の確定」ごとにしか起きないので、これで足りる。大きさが問題になったら、そのときに高頻度のものだけ差分に落とす（先に測ってから決める）
- **モデルの適用と SQLite への保存は、コマンドの中で続けて行い、両方成功してから返す。** 失敗したらモデルへの変更も捨てて `Err` を返す。画面はまだ何も変えていないので、巻き戻すものがない。「メモリを先に変えて、非同期で保存して、失敗したら巻き戻す」はやらない
- **イベントは Rust から webview への一方向だけ。** `board:changed`（ほかのウィンドウが盤面を変えた）、`app:action`（メニューが押された）、`capture:result`（キャプチャの保存が終わった）の 3 つ（`crates/app/src/events.rs`）。webview から Rust への通知はコマンドで行う
- **失敗は `Result<T, AppError>` で返し、判断の材料をコマンド側が付ける。** `kind`（`Save` / `BoardIo` / `Export` / `Shortcut` / `Validation`）、使う人が手を打てる言葉に直した `title` と `detail`、入力欄に返すときだけ `field`。`Validation` は入力欄の脇に、それ以外はダイアログに出す

### 境界を越える値

**型定義は `ts-rs` が Rust から書き出す。** 手で 2 か所に書くと必ずずれるので、生成物をコミットして CI で差分を見る（`web/src/ipc/types/`、`make types`）。

| 値 | 形 | 理由 |
| --- | --- | --- |
| ID（`i64`） | JSON の数値 | `board_id << 32` で名前空間を切っているので、ボードが 2^21（約 209 万）を超えると JavaScript の安全な整数（2^53）から外れる。実用上は当たらないが**当たったら黙って壊れる**ので、`crates/core` に「ID は 2^53 未満」を確かめるテストを置く |
| 期限（`NaiveDate`） | `"YYYY-MM-DD"` の文字列 | 時刻を持たない規則をまたいでも壊さないため。`Date` にしない（タイムゾーンで日付がずれる） |
| 時刻（`created_at` 等） | epoch **ミリ秒**の数値 | 表示のときだけ webview がローカル時刻に直す。`db` の `now()` が `as_millis` なので、秒だと思って読むと 1970 年が出る |
| 鍵の名前 | camelCase（`#[serde(rename_all)]`） | 受け取るのは TypeScript なので、そちらの流儀に寄せる |

`i64` を `bigint` に生成させない（`.cargo/config.toml` の `TS_RS_LARGE_INT=number`）。`bigint` になると `JSON.parse` が返す数値と型が食い違い、生成物と実際の値が黙って外れる。

### 盤面とカード

- **期限は日付のみ**、`TEXT` の `'YYYY-MM-DD'` で持つ。時刻は持たない。必要になった時点で `due_time` を足す
- **期限は文字で打ち、読み方は webview に 1 つだけ置く**（`web/src/model/due.ts`）。欄はテキスト欄で、`9/12` `明日` `金` `+3` `来週` `今週末` を受ける。基準日は引数で渡し、`parseDueDate` の中で時計を読まない。読めない文字列はコマンドを呼ばずに `Validation` で欄の脇に返す。打った文字をどう読んだかは、確定する前に欄の下に出す。**コマンドが受けるのは `"YYYY-MM-DD"` か空文字だけ**で、`parse_stored_due_date` はそれが日付として成り立つかだけを見る（[ADR 0031](adr/0031-typing-a-due-date.md)、[ADR 0039](adr/0039-the-board-model-moves-to-typescript.md)）
- **並べ替えは一時的なビューではなく `position` の書き換え**として行う。見た目の位置と本来の位置が食い違わないようにする
- **履歴に残すのはカードのライフサイクルだけ**（`created` / `moved` / `archived` / `restored` / `deleted`）。カラム内の並べ替えと属性変更は残さない。既存データを遡って生成しない
- **Undo のスタックと `card_events` は共有しない。** 寿命（セッション / 永続）と目的（取り消し / フローの記録）が違う
- **保存はボード本体と履歴を 1 トランザクションで行い、失敗したらメモリ上の状態と `pending_events` の両方を捨てる**
- **1 つのデータベースを開けるのは 1 プロセスだけ。** 起動時にデータベースの隣のロックファイル（`<データベース名>.lock`）を握り、握れなければ理由を出して終了する。差分保存は「自分の知らない行」を消すので、2 プロセスが同じファイルを持つと、あとから保存したほうがもう片方の追加を黙って消す。印を PID ファイルではなくファイルロックにするのは、異常終了しても OS がロックを落とすため（[ADR 0004](adr/0004-one-process-per-database.md)）
- **ロックはデータベースのパス単位。** `EKANBAN_DATABASE` を使い分けて並べて動かす使い方を潰さない。`tauri-plugin-single-instance` は使わない——あれはアプリ 1 つに対する制限で、この規則を壊す
- **「終わったものの置き場」であることは、カラムの 1 bit（`Column.done`）で表す。** 何本でも立てられる——「完了」と「キャンセル済み」は別の終わり方だが、もう手を動かさない点では同じなので、区別せず同じ扱いにする。カードには完了フラグを持たせない——Kanban ではカードの状態は**どのカラムにあるか**で表れている（開始日を入れない判断と同じ筋。[検討して入れないと決めたもの](#検討して入れないと決めたもの)）。切り替えは `set_column_done` の 1 コマンドで、Undo も 1 手（[ADR 0038](adr/0038-a-column-that-means-done.md)）
- **`done` のカラムのカードは、期限の件数に数えない。** アーカイブ済みを数えないのと同じ理由で、終わったものに期限切れも本日期限も無い。数える場所は SQL（`load_boards_as_of`）・`Board::due_counts`・`StoredBoard::summary` の 3 か所すべてで、件数から辿る先（`firstDueCard`）も同じ条件にする——押した数と着いた場所が食い違わないように（[ADR 0038](adr/0038-a-column-that-means-done.md)）
- **`done` を移行で推測しない。** 既存のデータベースでは 1 本も立てない。カラム名（「完了」「Done」「済」）から当てると、外したボードでは何も起きず、当たったボードでは黙って期限の件数が変わる。新しく作るボードには「やること」と「完了」を置き、後者を立てた状態で始める（[ADR 0038](adr/0038-a-column-that-means-done.md)）
- **初回に見えるものに、消す前提のものを置かない。** 空のデータベースを開いたときに作るのは「やること / 進行中 / 完了」の 3 カラムだけで、カードは 1 枚も入れない（`Board::first_run`）。使い方を伝えるカードは、読み終わったら消す手間を全員に配ることになり、消したあともアーカイブか `card_events` に残る。カラムだけは置く。0 カラムだと最初にやることが「カラムを作る」になり、Kanban の形が伝わらない
- **初回のシードとテストの土台を同じ関数にしない。** `Board::first_run()`（production）と `Board::fixture()`（`#[cfg(test)]`）に分ける。1 つが両方を兼ねると、初回の見た目を直すつもりで中身を変えたときにテストが壊れる
- **自動バックアップの世代は「起動ごと」ではなく「1 日ごと」に刻む。** ファイル名に日付を入れ、その日のファイルが既にあれば取らない。起動ごとに刻むと、壊したあとに起動し直しただけで無事だった世代が押し出される（[ADR 0003](adr/0003-daily-backup-generations.md)）
- **控えを取るのは起動時で、終了時ではない。** 終了時に取ると、壊した状態のほうを保存することになる。書き込みは `.part` に対して行い、完了してから `rename` する。途中でアプリが終わっても、中途半端なファイルが世代として残らない
- **控えが守るのは人的ミスとアプリのバグまで。** `backups/` はデータベースと同じディレクトリにあるので、ディスク障害や誤ったディレクトリ削除からは守れない。持ち出し先の管理を始めるとクラウド同期の設計になり、[スコープ外](#スコープ外)に入る。境界はマニュアルに書いて、あとはユーザーのバックアップに任せる

### 絞り込みと検索

- **判定は webview に 1 つだけ置く**（`web/src/model/search.ts`）。全角半角と大文字小文字の正規化（`normalizeSearchText`、`cardMatchesSearch`、`parseCardNumberQuery`）と `filterCards` はここにあり、盤面も手元にあるので**打鍵のたびに往復しない**。2 つ持てば、ずれた日にカードが見つからなくなる——**どちらに置くかではなく、1 つであることが規則**（[ADR 0039](adr/0039-the-board-model-moves-to-typescript.md)）
- **期限の状態（`due_status`）は Rust に残っている。** ボード一覧の件数を数えるのが SQL と `Board::due_counts` なので、判定はそちらと同じ場所にある（[ADR 0011](adr/0011-due-counts-in-the-board-list.md)、[ADR 0038](adr/0038-a-column-that-means-done.md)）
- **ボードでは絞り込みはカードを隠さず減光する。** 隠すとドロップの挿入位置が曖昧になり、D&D の意味が変わるため
- **アーカイブ表示だけは、絞り込みから外れたカードを隠す。** ここには D&D が無いので減光の理由が効かず、溜まる場所なので薄く並んでいても探せない。見出しに「一致した件数 / 全件数」を出し、並びはアーカイブした日の新しい順で日ごとに見出しを付ける（[ADR 0010](adr/0010-hiding-instead-of-dimming-in-the-archive.md)）
- **カード番号へは検索欄から辿る。** 検索欄に `#` と数字だけを打ったときは、その番号のカードだけを残す。`#イベント` のような数字でない語は番号として読まず、文字列検索に落ちる。番号を指定して開く別のコマンドは持たない（[ADR 0008](adr/0008-reaching-a-card-by-its-number.md)）
- **絞り込みの条件は検索とタグの 2 つに保つ。** 期限は表示するだけで、絞り込みの条件にしない（使い道が無かったので #32 で外した）。条件を増やすと「なぜこのカードが暗いのか」が読めなくなる
- **タグでの絞り込みはカード上のタグチップから行う。** ヘッダにタグを一覧しない。タグが増えるほどヘッダが混み、絞り込みたいタグはたいてい目の前のカードに付いている。ただし絞り込み中はヘッダにそのタグを 1 つだけ出す。減光の理由が画面から読めなくなるため
- **期限の件数は、ボード一覧の各行に出す。** 期限は通知しないので見に行かなければ気づけず、ボードが増えると見に行く先も増える。件数は `load_boards` の 1 クエリの中で SQL が数える。畳んだ帯では全ボードを合わせた印だけを出す。新しいビューは足さない（[ADR 0011](adr/0011-due-counts-in-the-board-list.md)）

### 画面の作り

TypeScript + React + Vite（[ADR 0019](adr/0019-typescript-react-vite-for-the-webview.md)）。分解は `web/src/` の `ipc` / `state` / `shell` / `board` / `panel` / `capture` に沿う。状態管理ライブラリは、持つ状態が少ないので入れない（同 ADR）。

- **色は 1 か所（`web/src/styles.css` のカスタムプロパティ）で決める。** `#rrggbb` の直書きはタグの色だけに許す——ユーザーの指定と、`web/src/panel/tags.ts` の自動の色みほんとチップの文字色、そして置き場所の移行が読む「かつての既定色」（`crates/core/src/store.rs`）
- **色だけに意味を持たせない。** アイコンか文言で必ず区別できるようにする
- **`--color-*-foreground` は、対応する背景の上に載せるための文字色。** `danger-foreground` を素の面の文字色に使うと背景と同化して読めない。カードやフォームの上に文字を置くときは `danger` `info` のような背景用の色のほうを文字色に使う。`accent` は淡いホバー背景なので、文字色には使わない
- **テーマの判定を JavaScript に持たせない。** 「ライト」「ダーク」は `<html>` の `data-theme` で決まり、「システムに合わせる」はその属性が無い状態にして `prefers-color-scheme` にそのまま任せる。OS の設定が変わったときアプリ側は何もしない
- **スクロールする要素から高さの決まった箱までの間にある flex アイテムすべてに `min-height: 0` を付ける。** flex アイテムの `min-height` は既定が `auto`（中身より小さく縮まない）で、0 に落ちるのは**その要素自身がその軸に `overflow` を持つときだけ**。間に挟まる祖先が縮まなければ、スクロールする要素も引き伸ばされてはみ出しが起きず、スクロールが始まらない。#43 はこれで、`board-content` が横の `overflow` しか持たず、カードの枚数だけ縦に伸びていた。軸を取り違えないこと
- **webview だから要る手当ては 1 か所（`web/src/shell/harden.ts`）で切る。** 散らすと、どれを切ったか数えられなくなる。既定の右クリックメニュー、リリースビルドでの再読み込みと devtools、既定のドラッグ、拡大縮小、macOS の 2 本指スワイプによる履歴移動
- **フォントはシステムのものを使う。** web フォントを読み込まない。README の「ネットワーク接続を必要としない」がそのまま設定で守られる（`tauri.conf.json` の CSP は `default-src 'self'`、capability は使うものだけを並べる）
- **入力欄の初期値に、案内の文言を入れない。** 案内は placeholder で出す。既定値として入れると、消し忘れがそのままデータになる（#36）。任意の項目はその旨も placeholder に書く
- **入力欄の枠は、触る前から出す。** 見出しを置かず placeholder で名前を言う欄（カードのタイトル・期限・説明）でも、枠と余白は最初から据え置きにする。触ったときだけ枠が現れる作りは、そこが打てる場所だと読めないうえ、触った瞬間に余白まで変わって文字が動く（#168）。触っているあいだに変えてよいのは枠の色だけ（`--color-info`）
- **1 行の入力欄では `Enter` で確定する。** カードのタイトル、期限、カラム名、タグ名、検索のように改行の要らない欄は `Enter` で保存し、`Escape` で取り消す。複数行の欄（カードの説明）では取らない。改行のほうが要るため、カードの編集パネルで `Enter` を拾うのは 1 行の欄の中だけにする
- **IME の変換中かは `web/src/shell/ime.ts` の `isComposing()` で判定する。** `KeyboardEvent.isComposing` を直に読まない。WebKit は変換を確定する `Enter` の `keydown` より先に `compositionend` を出すので、その `keydown` は `isComposing === false` で届く。変換に伴う `keydown` はどのエンジンでも `keyCode` が 229 になるので、そちらも見る（#124、[ADR 0029](adr/0029-detecting-ime-composition.md)）
- **常用しない操作を画面に常時出さない。** カードの操作は右クリックメニュー、カラムの操作は `…` メニュー、タグの編集・削除はメニューから開くタグ整理パネルに集約する。`danger`（赤）はダイアログの確定ボタンとメニュー内の削除項目だけに使う
- **タグを作れるのは、タグ整理パネルと、カード編集パネルのタグ欄の 2 か所。** 後者は「いま書いているカードに付ける」ためのもので、打った名前のタグが無ければその場で作る（前後の空白と大文字小文字を無視して突き合わせるので、同じ名前が 2 つできることはない）。**どちらの道でも、作るときに色は選ばせない**。名前の変更・色・削除はタグ整理パネルにしか置かない（[ADR 0027](adr/0027-creating-tags-while-editing-a-card.md)、[ADR 0044](adr/0044-tags-get-their-colour-automatically.md)）
- **タグの色は自動で付ける。** 色を決めていないタグ（`color` が空）は、その ID から `web/src/panel/tags.ts` の並びを引いて描く。ID から引くので、ほかのタグを消しても色は動かない。チップの文字色は**そのチップの背景から**決める（濃いほうと淡いほうのうち、コントラスト比の大きいほう）——テーマの文字色をそのまま載せると、濃い色に沈むか淡い色に溶ける。ユーザーが色を決めたタグは、その色をそのまま使う（[ADR 0044](adr/0044-tags-get-their-colour-automatically.md)）
- **`done` のカラムのカードはトーンダウンして描き、`opacity` は使わない。** 期限は日付だけを `muted` で出し（`⚠` `◷` と「N日超過」「あとN日」は落とす）、タイトル・説明・チェックリストは `--color-muted-foreground`、タグのチップは彩度を落とす。カード全体の `opacity` は**絞り込みの減光が使っている**ので、終わったものは**色**、絞り込みは**濃さ**で分ける。暗いカードの理由が 2 つあると、どちらなのか読めなくなる。カラムのヘッダには `✓` を出す（[ADR 0038](adr/0038-a-column-that-means-done.md)）
- **カード表面の高さは、チェックリストの項目数のような可変の要素で変えない。** ドラッグゴーストの大きさと挿入位置の判定が安定しなくなるため
- **説明は Markdown のエディタ（Lexical）で書き、保存するのは Markdown の文字列。** `Card.description` の型もデータベースも変わらない。打ちながら整うのは `**太字**` `*斜体*` `` `コード` `` `# 見出し` `- 箇条書き` `- [ ] チェック項目` `> 引用` と、打った URL のリンク化まで（[ADR 0033](adr/0033-a-markdown-editor-for-the-description.md)、[ADR 0037](adr/0037-a-list-that-ends-where-you-stop-typing.md)）
  - **箇条書きは、何も打っていない項目で `Enter` を押すと終わる。** 続けるかどうかを決めるのは打ち手で、`Enter` は「次の項目」と「箇条書きの終わり」を兼ねる。この判断は `@lexical/list` の `ListPlugin` が持っているものをそのまま使い、**`Enter` を自分で捕まえない**——入れ子や番号の振り直しまで同じ判断で動く必要があり、2 か所に書くと必ず食い違う
  - **チェック項目は説明の中に書ける。** `- [ ] ` と打てば印が出て、押せば `- [x] ` で保存される。カードのチェックリスト欄（`Card.checklist`）とは別物で、**進み具合をカード表面に出すのはこれまでどおり後者だけ**（[ADR 0037](adr/0037-a-list-that-ends-where-you-stop-typing.md)）
  - **リンクとして拾うのは `http://` と `https://` だけ。** 裸の `example.com` や `ftp://` まで拾うと、URL でない文字列がリンクになる。末尾の句読点と閉じ括弧は落とすが、`)` は対応する `(` が URL の中にあるときだけ残す。どこからどこまでが URL かを拾う規則は webview 側（`web/src/panel/links.ts`）にある——エディタではリンクが文書の節そのものなので、外から位置で塗る形にできない
  - **開くには修飾キー（`Cmd` / `Ctrl`）＋クリックを要求する。** 素のクリックは「そこにカーソルを置く」という編集の意味を既に持っている
  - **開いてよい形かどうかを決めるのは Rust**（`commands::openable_url`）。説明はユーザーが打った文字列なので、`file://` や `javascript:` を混ぜられる場所
  - **説明の欄は、打った分だけ縦に伸びる。** 中身が見えないまま書き続けさせない（#89）。空でも 4 行ぶんは開けておく——中身に合わせるだけだと、説明の無いカードでそこが何を書く場所なのか読めなくなる

### ドラッグ＆ドロップ

README が「いちばん大事にしています」と書いているところ。**受け入れ条件は番号で呼びます**——コードとテストがこの番号で参照しています（[ADR 0020](adr/0020-pointer-based-drag-and-drop.md)）。

| # | 条件 |
| --- | --- |
| 1 | 掴んだカードのゴーストがポインタに遅れずついてくる |
| 2 | 落とす位置（どのカラムの何枚目か）が、落とす前に見て分かる |
| 3 | カラムの端にポインタを寄せると自動でスクロールし、押したまま端で止めても滑らかに続く |
| 4 | 減光しているカードの位置にも落とせる（絞り込み中に挿入位置が変わらない） |
| 5 | カラムそのものの並べ替えも、カードと同じ操作感でできる |
| 6 | キーボードでもカードを動かせる |
| 7 | 落としてから画面が確定するまでに間が空かない |
| 8 | 3 つの webview（WKWebView / WebView2 / WebKitGTK）で 1〜7 が同じ |

- **HTML5 の drag events（`dragstart` / `dragover` / `drop`）は使わない。** ゴーストの見た目を OS に取られ、`dragover` の間引きも制御できず、webview ごとに挙動が揃わない。ポインタイベントに載せる（`@dnd-kit/core`、[ADR 0022](adr/0022-dnd-kit-core-for-drag-and-drop.md)）
- **落とす位置を決めるのはこちらのコード。** ライブラリに任せるのは掴む・追う・落とすまでで、どのカラムの何枚目かは `web/src/board/dnd.ts`（キーボードは `keyboard.ts`）が決め、その判定を単体で確かめる。ライブラリは運ぶだけなので、差し替えられる
- **ドラッグ中は webview の中だけで完結させ、`drop` の瞬間に `move_card` / `move_column` を 1 回だけ呼ぶ**

### メニューとキー割り当て

- **どのプラットフォームでもメニューバーを出す。** macOS はアプリメニュー、Windows と Linux はウィンドウのメニューバーで、どれも OS が描く（[ADR 0015](adr/0015-a-menu-bar-on-every-platform.md)）
- **メニューは `crates/app/src/menu.rs` でデータとして組み、`cfg!` を構成の途中に置かない。** macOS 用とそれ以外用の並びは、どちらも常に組み立てられる形で書く。そうでないとテストが両方を突き合わせられず、片方からだけ項目が落ちても気づけない
- **メニューのアクセラレータは、フォーカスに関係なく効いてよいキーにだけ付ける。** OS のメニューは webview より先にキーを取るので、テキスト編集に譲らなければならないキーに付けると、入力欄で打っている最中の操作まで盤面に食われる。譲るキーはメニュー項目だけ残し、キーは webview の `keydown` で受ける
- **`Cmd/Ctrl+Z` と `Cmd/Ctrl+Shift+Z`（Undo / Redo）にはアクセラレータを付けない。** `web/src/shell/keys.ts` が受け、入力欄にフォーカスがあれば既定の動き（webview 自身の編集履歴）に任せ、無ければ盤面の Undo に振り分ける
- **入力欄・検索欄にフォーカスがある間はボードのショートカットを無効にし、IME とテキスト編集を優先する**
- **`Enter` / `Escape` / 矢印 / 修飾キー付きの矢印は webview の `keydown` で受け、メニューには出さない**
- **カット / コピー / ペースト / すべてを選択は、OS の既定のメニュー項目に任せる。** 自分で実装しない
- **アプリ独自の割り当ては `CmdOrCtrl+…` で書く**（macOS では Cmd、ほかでは Ctrl）。`Cmd+…` を直に書いてよいのは macOS の並びの中だけ。フルスクリーンは macOS が `Cmd+Ctrl+F`、ほかは `F11`。終了とウィンドウを閉じるの項目を自分で持つのも macOS 以外だけ（macOS は OS の項目が持つ）（[ADR 0009](adr/0009-per-platform-key-bindings.md)）
- **メニューが押されたら `app:action` を webview に投げ、フロント側の 1 本の dispatcher がキーボードからの経路と同じ関数を呼ぶ**（`web/src/shell/actions.ts`）。どちらから来ても行き先が 1 つなので、片方だけ効かない状態を作れない
- **どの OS かは Rust から受け取る**（`StartupState.platform`）。`navigator.userAgent` は webview が名乗るもので、Tauri のプラットフォームとは限らない

### ウィンドウ

- **ウィンドウの矩形は `app_state` に保存し、起動時に復元する。** `tauri-plugin-window-state` は使わない——データの置き場所を 2 つに割らないため。復元する前に、表示可能なモニタに載っているかを確かめる
- **全画面・最大化・最小化のときの矩形は保存しない。** 戻したときに出るのはその状態の矩形で、次の起動で画面いっぱいの「ふつうのウィンドウ」が開くことになる
- **Wayland ではウィンドウの位置を復元しない。** クライアントが自分の画面上の位置を知ることも指定することもできないため、アプリ側では直せない。大きさだけが戻る。直せないものを直せるように見せず、マニュアルにそう書く
- **矩形を保存するのはボードのウィンドウだけ。** キャプチャウィンドウは毎回画面中央に出す
- **macOS ではウィンドウを閉じてもプロセスが残るので、Dock から開き直せるようにする**（`RunEvent::Reopen`）。受け口が無いと、ウィンドウを閉じたあとは終了して起動し直すしか道が無くなる
- **ウィンドウを開き直すときは、状態をデータベースから読み直す。** 閉じている間もクイックキャプチャはカードを足せるので、閉じたときのメモリ上の値で開き直すと古い盤面が出る。読み込みは `load_startup_state` の 1 本にして、初回の起動と開き直しで経路を分けない

### Linux のデスクトップ統合

- **ユーザーのディレクトリで完結する導線を残す。** デスクトップエントリ・アイコン・実行ファイルを `~/.local`（XDG のユーザーディレクトリ）に入れる `script/install-linux` を持ち、root を要求しない。`.deb` を配ってもこれは消さない。エントリの `StartupWMClass` は、ウィンドウが名乗る `WM_CLASS`（`crates/core/src/lib.rs` の定数。実行ファイルの名前から決まる）と必ず同じにする。食い違うとウィンドウがエントリに結びつかない。アイコンは縮小済みのものを `assets/icons/` にコミットし、ビルド時には作らない（[ADR 0013](adr/0013-linux-desktop-integration.md)）
- **xdg-desktop-portal を要求しない。** ファイルの選択は GTK のもの（`tauri-plugin-dialog` に `xdg-portal` の feature を付けない）、テーマは CSS の `prefers-color-scheme`。ポータルを通りうるのは「場所を開く」だけで、そこも D-Bus とファイル管理ソフトと `xdg-open` に落ちる（[ADR 0024](adr/0024-no-portal-requirement-on-linux.md)）

### クイックキャプチャ

- **グローバルホットキーが使えるのは macOS と X11 のセッションだけ。** Wayland にはアプリから使える共通の仕組みが無く、Windows はまだ実装していない（`shortcut::platform_support`）。X11 の実装は使えない環境でも登録が成功したように見える（スレッドの生成しか確かめず、そのスレッドが死んでいても `register` が `Ok` を返す）ので、戻り値を信じずに環境変数で先に判定する。使えない環境ではメニュー項目を無効にし、理由を文言に出す。macOS では OS の権限は要らない——`RegisterEventHotKey` で登録でき、権限が要るのはキー入力そのものを覗く `CGEventTap` の方式だけ
- **グローバルホットキーは既定で登録しない。** ユーザーが割り当てて初めて有効になる。全画面でその組み合わせを奪うので、断りなく取ると、ほかのアプリが動かなくなった理由を追えなくなる。修飾キーを 1 つも含まない割り当ても同じ理由で受け付けない
- **登録できていない割り当てを保存しない。** 登録に失敗したらその場で理由を出し、設定は変更前のまま残す。起動のたびに黙って失敗する状態を作らない
- **`app_state` に入る割り当ての表記は変えない**（`ctrl-shift-n` の形）。Tauri の表記（`"Control+Shift+N"`）との変換は `crates/app/src/shortcut.rs` が両方向で行う。保存の形を変えれば移行が要り、読めなかった割り当ては黙って消えるので、変換のほうを持つ
- **割り当ての捕捉は webview の `keydown` で受け、`event.code` から組み立てる。** `event.key` は配列と修飾キーで変わるので、押された物理キーのほうを見る
- **割り当てを捕まえている間は、自前のメニュー項目がキーを取らない状態にする。** OS はメニューの割り当てを webview より先に当てるので、付いたままでは `Cmd+N` のような組み合わせの `keydown` がダイアログに届かない。アクセラレータを外すのと項目を無効にするのを**両方**行う——muda は macOS でアクセラレータを外せない。付け直す形は控えを持たず `menu::sections()` から作り直す（[ADR 0030](adr/0030-capturing-a-shortcut-needs-the-menu-out-of-the-way.md)）
- **押されているキーを、押している間そのまま画面に出す。** 修飾キーだけの途中も出す。割り当てたあともダイアログを閉じず、登録された組み合わせをその場に残す。キーが届いていない・届いて断られた・届いて登録できたの 3 つが、画面で区別できることが条件（[ADR 0030](adr/0030-capturing-a-shortcut-needs-the-menu-out-of-the-way.md)）
- **保存されているのに登録できていない割り当ては、理由まで持って画面に出す。** 起動のときの登録の失敗を捨てずに残し、割り当てのダイアログが読む。新しい割り当ての登録に失敗したら、外した前の割り当てを登録し直す——設定は変更前のまま残るので、戻さなければ次の起動まで効かない割り当てができる（[ADR 0030](adr/0030-capturing-a-shortcut-needs-the-menu-out-of-the-way.md)）
- **キャプチャの保存は `capture_card` コマンドを通し、ボードと同じ保存経路に乗せる。** キャプチャウィンドウから直接 SQLite を触らない。経路を通せば、カラムの末尾に足す・1 回の保存で永続化する・`created` イベントが 1 件積まれる、がそのまま満たされる
- **キャプチャ先はアプリ全体で 1 つ。** ボードごとには持たない。ボードを切り替えても入れ先が変わらないことが、この機能の使い勝手そのものだから。**既定も 1 つで、それは先頭のボード（サイドバーの一番上）の先頭カラム。** 指しているボードやカラムが消えていたら黙ってこの既定に戻す（[ADR 0028](adr/0028-a-single-default-quick-capture-target.md)）
- **開いていないボードへのキャプチャは Undo の対象にしない。** Undo のスタックは開いているボードのものなので、開いていないボードの操作を積む場所がない。積める場所を作ると「Undo を押したのに画面が変わらない」状態を作ることになる
- **キャプチャが書いたら `board:changed` を投げる。** ボードのウィンドウが開いていれば、そちらの盤面がその場で追いつく
- **閉じたあとのフォーカスの戻し先は、Linux では 1 つだけ保証する。** アプリ全体を隠す・直前のアプリへフォーカスを返すは Linux では実現できないので、そこは「ekanban 側では決めない」とマニュアルに OS 別で書く（[ADR 0012](adr/0012-focus-after-quick-capture-on-linux.md)）

### アプリが伝えること

行き先で分ける（[ADR 0016](adr/0016-where-the-app-says-things.md)）。常時表示のステータス行は持たない（#86 で撤去）。

- **ダイアログに出すのは 2 種類だけ。** 使う人が手を打たないと直らない失敗（保存、ボードの読み書き、書き出し・コピー、ホットキーの登録）と、アプリの外にファイルを書けたこと（書き出し・コピーの完了。パスと、そこを開く導線を付ける）。成功を伝えるのは、画面に痕跡が残らないファイル書き出しだけ
- **押せるコントロールがあるのに断る操作は、理由を言わずにそのコントロールを無効にする。** 空のカラムの「アーカイブ」、最後の 1 つになったボードとカラムの `…` の「削除」、名前が空のままの確定ボタン。押せない理由は、その場の状況から読み取れる形にする
- **メニューの項目はこの限りではない。** 押せるかどうかを常に映すには盤面の状態を追い続けることになるので、メニューからの拒否はダイアログで理由を返す
- **それ以外の拒否・キャンセル・変更なし・進行中は何も言わない。** キーボードとメニューからしか来ない拒否も無言で何もしない
- **報告と確認はアプリ内の `<dialog>` で出す。** OS のメッセージダイアログは使わない。文言・ボタン・「場所を開く」導線を自分で決められること、Playwright から見えることの 2 つが理由。ファイルの**選択**だけは OS のネイティブなダイアログ（`tauri-plugin-dialog`）に任せる——保存先を選ぶ画面を自分で作るのは、作りたいものではない
- **確認ダイアログは Undo の代わりではない。** 出すのは「Undo で戻せない」か「1 操作で複数件が消える」ものに限る。すべての削除に出すと、読まずに押す確認になって役に立たなくなる
- **起動できないと分かっているなら、ウィンドウを開かない。** 開いてしまうと、枠もメニューバーも出ているのに中身だけが空という、**動いているように見えて動いていない**画面になる。デバッグビルドが Vite の開発サーバに繋がらないときがこれで、webview の「Connection refused」を見せる代わりに、次に何を打てばいいかを出して終わる（`run.rs` の `check_dev_server`）
- **webview の未捕捉例外は `log_frontend_error` で Rust 側と同じログに落とす。** webview の失敗が黙って消えると、原因を追う手段が無くなる。Rust 側のパニックフックと起動失敗の記録（`crates/core/src/diagnostics.rs`）はそのまま

### テスト

層の分け方（中核 / コマンド / 画面 / 部品）と書き方は [開発の手引きの「テスト」](DEVELOPMENT.md#テスト) にある（[ADR 0021](adr/0021-two-layer-testing-for-the-webview.md)）。ここに置くのは、その形を保つための決まりごと。

- **偽物のバックエンドを TypeScript で書かない。** `ekanban-harness` が `crates/app` のコマンドを同じ名前で HTTP に出し、答えるのは本物の `ekanban-core`。モデルの挙動がテストの中でだけ違う、が起きない。**ブラウザで配る版（`crates/web`）も同じ**で、そちらは同じコマンドを wasm に組み直して動かす（[ADR 0035](adr/0035-a-browser-build-of-the-real-core.md)）
- **画面の振る舞いは、本物の画面を開いて確かめる。** 純粋関数に切り出して単体で確かめるだけでは、配線（ハンドラの付け忘れ、入力欄にフォーカスがある間の抑止）が抜けても気づけない。切り出し自体は続けるが、それはテストの代わりにはならない
- **画面のテストは、画面と SQLite の両方を見る。** `web/e2e/harness.ts` の `invoke()` で盤面を読み直す。画面に出ているだけでは、保存の配線が抜けていても気づけない
- **待ち合わせは要素の出現で書き、実時間の `sleep` を入れない。** 入れると、保存の完了を待たないテストが偶然通るようになる
- **webview の実装ごとの差は、Playwright では担保できない。** Playwright が繋がるのは Chromium / Firefox / WebKit であって、WKWebView・WebView2・WebKitGTK ではない。E2E は Chromium と WebKit の 2 つで回し、実物での確認はリリース前に手で行う（[ADR 0023](adr/0023-verifying-the-webview-engines.md)）
- **`unsafe_code = "forbid"` は Rust 側に残る。** TypeScript 側は `tsc --strict` と ESLint の型付き規則で代える。ファイルを通すために規則を切らない

### ビルドと配布

- **必須チェックの名前 `Check and test` を変えない。** ルールセットが名前で見ており、変えると全 PR がマージ不能になる
- **CI は 3 つの OS でビルドとテストを回す。** `#[cfg(target_os)]` で分かれるコードは、その OS で組んで初めてコンパイルされる。fmt と clippy は結果が OS で変わらないので `Check and test` だけで見る（[ADR 0006](adr/0006-ci-on-three-platforms.md)）
- **`web/src/ipc/types/` は手で書かない。** `ts-rs` が Rust の型から書き出し（`make types`）、生成物をコミットして CI で差分を見る
- **大文字と小文字だけが違うファイル名を作らない。** macOS と Windows のファイルシステムは大文字小文字を区別しないので、`Foo.tsx` と `foo.ts` が同じ名前に潰れ、Linux では通ったビルドがそこだけ落ちる
- **配るものは Tauri のバンドラが作る。** macOS は `.app`（`.zip`）と `.dmg`、Linux は `.deb` と `.AppImage` に加えて `.tar.gz`（root を要求しない導線）、Windows は `.zip` と NSIS のインストーラ。ad-hoc 署名の指定は `tauri.conf.json` にあり、手元で組んだものと CI が組んだものが同じ署名になる（[ADR 0014](adr/0014-unsigned-apple-silicon-only-macos-builds.md)）
- **`cargo run` はアプリを起動する。** ワークスペースの `default-members` を `crates/app` にしてある。**代わりに `--workspace` を省いた `cargo` のコマンドはそこだけを見る**ので、Makefile と CI は必ず `--workspace` を付ける
- **ブラウザに SQLite を積まない。** `wasm32-unknown-unknown` に組んだ SQLite だけで 2.1 MB あり、こちらのコード全部より 5 倍大きい。ブラウザ版の置き場所は JSON で、盤面は文字列 1 つとして `localStorage` に入る（[ADR 0036](adr/0036-one-model-two-places-to-put-it.md)）
- **ブラウザ版に、盤面の判断を書かない。** `crates/web` に入るのは環境の差だけ（保存先、ファイルの持ち出し方、URL の開き方）。メニューの構成も Rust が返し（`menu::web_sections`）、ページはそれを描く。ブラウザにできないことは**消さずに灰色にして、理由を文言に入れる**（[ADR 0035](adr/0035-a-browser-build-of-the-real-core.md)）
- **ブラウザ版だけが、どの OS かをページから受け取る。** `wasm32-unknown-unknown` はどの OS でもないので、コンパイル時に決められない。配るアプリの経路は変えない（[ADR 0009](adr/0009-per-platform-key-bindings.md)）
- **Node の依存を増やさない。** `cargo` だけで完結していたところに増やしたものなので、版はロックファイルで固定し、入れるのは `npm ci` だけにする

### 根拠の書き方

- **根拠として、このリポジトリに無いものを挙げない。** コメントも文書も、いま開けるコード・この文書の決まりごと・ADR だけを指す。消えた実装との一致を理由にすると、読み手は挙げられたものを開けないので、その根拠が正しいかどうかも、いま守れているかどうかも確かめられない。**経緯は ADR にだけ残す**——ADR は書き換えない文書なので、消えたものの名前が出てよいのはそこだけ（[ADR 0026](adr/0026-gpui-stays-only-in-the-adrs.md)）

## 検討して入れないと決めたもの

検討のうえ実装しないと決めたものです。「思いつかなかった」のではなく「判断した」ことを残すために書いています。前提が変わったら、ここを書き換えて ADR を残します。

| 項目 | 判断の理由 |
| --- | --- |
| 開始日（`defer_date`） | Kanban では「まだ着手しない」を**カラムが表している**。Backlog / Someday というカラムがあるのに日付でも同じことを表すと状態の表現が二重になり、「Ready カラムにあるが開始日が来ていないカード」が何を意味するのか答えられない。減光の条件も増える（[絞り込みと検索](#絞り込みと検索)） |
| 保存されたビュー（Perspective） | 個人の 1 ボードでタグ数個・カラム数個の規模なら、絞り込みを手で作り直すコストはそもそも低い。ヘッダを混ませない方針とも合わない。OmniFocus の Perspective が効くのはプロジェクト数百のスケールがあってこそ |
| フラグ（1 bit の重要マーク） | タグで完全に代用できる。欲しくなる理由は操作コストなので、カードのコンテキストメニューでタグを直接トグルできるようにして解決した |
| カードの複数選択 | 主用途である「Done をまとめて片付ける」は `archive_column` ですでに満たされている。複数選択の D&D はゴーストの見せ方と挿入枚数の表現が難しく、最重視の D&D の直感性を落とすリスクが実利に見合わない |
| カラムの折りたたみ | 折りたたんだ列への D&D の振る舞い（落とせないのか、ホバーで展開するのか、末尾固定で落とせるのか）がどれも今の一貫性から外れる。カラム 3〜5 個の規模では横スクロールに困っておらず、困っていない問題への対処になる |
| WIP 上限 | カラムごとに枚数の上限を決めて超過を赤く出す機能を持っていたが、**個人ボードでは守らせる相手が自分しかいない**。守れない日は上限のほうを上げるか、赤いまま無視するかのどちらかにしかならず、どちらでも警告は意味を失う。「多すぎる」は枚数がそのまま出ているので見れば分かる（[ADR 0034](adr/0034-dropping-the-wip-limit.md)） |
| 見積ポイントと WIP のポイント制 | 個人ボードで見積の運用は続きにくく、空欄のまま放置されてポイント制が機能不全になる。枚数の粗さはむしろ「大きすぎるカードは分割しろ」という圧力として働く。加えて `card_events` から**実測のサイクルタイム**が取れる。見積は実測の代替なので、実測が取れるなら要らない |
| 添付ファイル・カバー画像 | ローカル専用なので絶対パスを持つだけで実装できるが、ファイルが移動・削除されたときの破綻の面倒を見る価値がこのアプリにはない |
| カレンダー / タイムラインビュー | D&D の落とし先がボードとカレンダーで二重になり、最優先の方針と正面から衝突する |
| コメント欄・アクティビティフィード | 単独ユーザーでは薄い。「いつ何が起きたか」は `card_events` が持つ |
| 2 つ目の起動から既存ウィンドウを前に出す | 動いているプロセスに「前に出ろ」と伝える経路（Unix ドメインソケット、D-Bus など OS ごとに違う仕組み）が要る。それは URL スキームの受け口と実質同じもので、URL スキームを保留にしている理由そのもの。片方だけ先に作ると、あとで二重の仕組みになる。2 つ目は理由を出して終了するに留める |
| アプリ内からの控えの復元 | 世代を選んで差し替える UI を作ると、開いているボードの破棄、保存中の待ち合わせ、失敗時のロールバック、Undo スタックの扱いが要る。戻す作業は年に数回で、そのために常時抱える複雑さに見合わない。控えはデータベースと同じ形式の 1 ファイルなので、アプリを終了してファイルを上書きすれば戻る。手順は `docs/MANUAL.md` にある |
| Intel Mac 向けの macOS ビルド | 動かせる Intel Mac が手元に無く、実機で一度も起動していないバイナリを「対応」として配ると、動かなかったときに答えられない。ソースからのビルドは通る（[ADR 0014](adr/0014-unsigned-apple-silicon-only-macos-builds.md)） |
| Developer ID での署名と公証 | Apple Developer Program の年額が要る。単独ユーザー向けのローカルアプリで、ソースが公開されていて自分でビルドできるものに対して、いま払う理由が無い。代わりに**初回起動の手順を macOS のバージョンごとに正しく書く**（[ADR 0014](adr/0014-unsigned-apple-silicon-only-macos-builds.md)） |
| メニューバー常駐（ステータスバーアプリ） | 常駐の価値はクイックキャプチャと通知にあるが、前者は常駐なしの小窓として実装したため常駐は要らず、後者はスコープ外。残るのは「ウィンドウを速く出す」だけで、Dock と `Cmd+Tab` で足りている。「アプリが起動している間しか効かない」が実際に不満になったら、そのときに再検討する |

## 変更の完了条件

issue を閉じる前に、すべて満たしていること。

1. `make check` が通る（`cargo fmt --check` / `clippy` / `cargo test` / `ekanban-core` の依存の検査と、`tsc` / `eslint` / `vitest`、生成した型に差分が出ないこと）
2. モデルの変更には `#[cfg(test)]` のユニットテストが付いている
3. コマンドを追加・変更した場合は、`crates/app/tests/commands.rs` が、返るスナップショットと SQLite に届いた内容の両方を見ている
4. 画面の操作（メニューのアクション、ショートカット、入力欄の保存とキャンセル）を追加・変更した場合は、`web/e2e/` に Playwright のテストが付いている（`make e2e`）
5. スキーマの変更には、旧バージョンの DB を開くマイグレーションテストが付いている
6. 入力欄を追加・変更した場合は、日本語 IME での入力を実機で確認している
7. 表示を変更した場合は、ライトとダークの両方で確認している
8. README と `docs/` の記述と食い違いが出ていない（README は使う人向け、`docs/MANUAL.md` は使い方、`docs/DEVELOPMENT.md` は構造とビルド）
9. **重大な決定をしたなら、[ADR](adr/README.md) に残してある。** 何が「重大」かは [`docs/adr/README.md` の「いつ書くか」](adr/README.md#いつ書くか) で判定する。この文書の決まりごとを足した・書き換えた・破ったなら、必ず要る
