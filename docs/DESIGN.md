# 設計の記録

README が使う人向けの入口、[マニュアル](MANUAL.md) が使い方、[開発の手引き](DEVELOPMENT.md) が構造とビルドを扱うのに対し、この文書は **決めたことと、決めなかったこと** を残します。

**進行中の作業は [GitHub issues](https://github.com/tokuhirom/ekanban/issues) で管理します。** 「次に何をやるか」はここには書きません。以前あったフェーズ別のタスク一覧と受け入れ条件は、残っていたものを issue に移してから削除しました。

ここに残すのは、issue を 1 つ閉じても消えない種類のこと、つまり後から来た実装が従うべき制約と、同じ検討を二度しないための判断の記録だけです。

**この文書は「いま従うべき規則」の一覧です。** 判断が変われば書き換えます。「なぜそうなったか」「何と迷ったか」は [設計判断の記録（ADR）](adr/README.md) にあり、そちらは書き換えません。経緯が要る規則には、行末に ADR へのリンクを付けてあります。

## 引き継ぐ設計の決まりごと

今後の実装が従うもの。破るときは、破る理由をここに書き足すこと。

- **期限は日付のみ**、`TEXT` の `'YYYY-MM-DD'` で持つ。時刻は持たない。必要になった時点で `due_time` を足す
- **絞り込みはカードを隠さず減光する。** 隠すとドロップの挿入位置が曖昧になり、D&D の意味が変わるため
- **並べ替えは一時的なビューではなく `position` の書き換え**として行う。見た目の位置と本来の位置が食い違わないようにする
- **履歴に残すのはカードのライフサイクルだけ**（`created` / `moved` / `archived` / `restored` / `deleted`）。カラム内の並べ替えと属性変更は残さない。既存データを遡って生成しない
- **Undo のスタックと `card_events` は共有しない。** 寿命（セッション / 永続）と目的（取り消し / フローの記録）が違う
- 保存はボード本体と履歴を 1 トランザクションで行い、失敗したらメモリ上の状態と `pending_events` の両方を捨てる
- **色だけに意味を持たせない。** アイコンか文言で必ず区別できるようにする
- **色は `ActiveTheme::theme()` から引く。** `rgb(0x…)` の直書きはユーザーが指定したタグの色だけに許す
- **`*_foreground` は、対応する背景の上に載せるための文字色。** `danger_foreground` を素の面の文字色に使うと背景と同化して読めない。カードやフォームの上に文字を置くときは `danger` `info` のような背景用の色のほうを文字色に使う。`accent` は淡いホバー背景なので、文字色には使わない
- **縦並び（`flex_col`）の直下に置いた要素は幅いっぱいに伸びる。** チップのように内容の幅で置きたいものは、横並びの行で包む
- **`overflow_y_scroll` を効かせるには、そこから高さの決まった箱までの間にある flex アイテムすべてに `min_h_0` が要る。** flex アイテムの `min-height` は既定が `auto`（中身より小さく縮まない）で、これが 0 に落ちるのは**その要素自身がその軸に `overflow` を持つときだけ**。スクロールする要素本体は `overflow_y_scroll` を持つので自動的に縮むが、間に挟まる祖先はそうではない。祖先が縮まなければスクロールする要素も引き伸ばされ、はみ出しが起きないのでスクロールが始まらない。#43 はこれで、`board-content` が `overflow_x_scroll` しか持たず（縦の `overflow` は `visible` のまま）カードの枚数だけ縦に伸びていた。軸を取り違えないこと。横に `overflow_x_scroll` を置いても縦の `min-height` は縮まない
- 入力欄・検索欄にフォーカスがある間はボードのショートカットを無効にし、IME とテキスト編集を優先する
- **アプリ独自のキーボードショートカットは `secondary-` で定義する。** `secondary` は macOS では Cmd、Linux と Windows では Ctrl になる。`cmd-` を使ってよいのは、macOS のシステムメニューの割り当て（`cmd-q` `cmd-h` `cmd-alt-h`）と、`Ctrl` を含む組み合わせ（`cmd-ctrl-*`）だけ。後者を `secondary-ctrl-*` にすると非 macOS で `Ctrl` が重なって潰れ、`secondary-s` や `secondary-f` と衝突する
- **グローバルホットキーが使えるのは macOS と X11 のセッションだけ。** Wayland にはアプリから使える共通の仕組みが無い。`global-hotkey` の X11 実装は使えない環境でも登録が成功したように見える（スレッドの生成しか確かめず、そのスレッドが死んでいても `register` が `Ok` を返す）ので、戻り値を信じずに環境変数で先に判定する。使えない環境ではメニュー項目を灰色にし、理由を文言に出す
- **グローバルホットキーは既定で登録しない。** ユーザーが割り当てて初めて有効になる。全画面でその組み合わせを奪うので、断りなく取ると、ほかのアプリが動かなくなった理由を追えなくなる。修飾キーを 1 つも含まない割り当ても同じ理由で受け付けない
- **登録できていない割り当てを保存しない。** 登録に失敗したらその場で理由を出し、設定は変更前のまま残す。起動のたびに黙って失敗する状態を作らない
- **クイックキャプチャの保存はボードの保存経路を通す。** キャプチャウィンドウから直接 SQLite を触らない。`save_lock` で守っている前提が崩れ、ボード側の非同期保存と競合する。`BoardView` に依頼すれば、カラムの末尾に足す・1 回の保存で永続化する・Undo の対象になる・`created` イベントが 1 件積まれる、がそのまま満たされる
- **ウィンドウの枠を自分で描くかは `Decorations` で決める。** 「Wayland かどうか」では見ない。X11 でもコンポジタが ServerSide を返さない構成はありうるし、Wayland でも Mutter 以外は返す。`Decorations::Client` のときだけ、掴んで動かすタイトルバーと、しまう / 拡大 / 閉じるを出す。縁とリサイズは gpui-component の `window_border()` に任せる（辺ごとの当たり判定がタイル配置で変わるので、自前で書くとスナップ時に存在しない縁を掴もうとする）（[ADR 0005](adr/0005-in-app-menu-without-a-menu-bar.md)）
- **gpui-component の `TitleBar` は使わない。** `TitleBar::window_options()` が `appears_transparent` と信号機ボタンの位置を要求し、macOS の見た目が変わる。枠を出したいのは装飾を寄越さない環境だけなので、そのために全プラットフォームの見た目を動かさない
- **Wayland ではウィンドウの位置を復元しない。** クライアントが自分の画面上の位置を知ることも指定することもできないため、アプリ側では直せない。大きさだけが戻る。直せないものを直せるように見せず、マニュアルにそう書く
- **1 つのデータベースを開けるのは 1 プロセスだけ。** 起動時にデータベースの隣のロックファイル（`<データベース名>.lock`）を握り、握れなければ理由を出して終了する。保存は差分の UPSERT のあとに「自分の知らない行」を消すので、2 プロセスが同じファイルを持つと、あとから保存したほうがもう片方の追加を消す。しかも両方の画面が自分の状態を出し続けるため、消えたことに気づけない。印を PID ファイルではなくファイルロックにするのは、異常終了しても OS がロックを落とすため（[ADR 0004](adr/0004-one-process-per-database.md)）
- **ロックはデータベースのパス単位。** `EKANBAN_DATABASE` を使い分けて並べて動かす使い方を潰さない
- **矩形を保存するのはボードのウィンドウだけ。** キャプチャウィンドウは毎回画面中央に出す
- **macOS ではウィンドウを閉じてもプロセスが残るので、Dock から開き直せるようにする。** gpui の `QuitMode::Default` が macOS でだけ「最後のウィンドウで quit しない」を選ぶ。`Application::on_reopen` に受け口が無いと、`Cmd+W` のあとは `Cmd+Q` で終了して起動し直すしか道が無くなる
- **ウィンドウを開き直すときは、状態をデータベースから読み直す。** 閉じている間もクイックキャプチャはカードを足せるので、閉じたときのメモリ上の値で開き直すと古い盤面が出る。読み込みは `load_startup_state` の 1 本にして、初回の起動と開き直しで経路を分けない
- **`≡` のメニューには macOS のウィンドウ操作を出さない。** 「しまう」「拡大／縮小」を置くのは、macOS の `Cmd+M` がメニュー項目のあるときだけ効くため。ほかの環境では最小化も最大化もウィンドウマネージャの仕事で、アプリのメニューに出す意味がない
- **クイックキャプチャ先はアプリ全体で 1 つ。** ボードごとには持たない。ボードを切り替えても入れ先が変わらないことが、この機能の使い勝手そのものだから。指しているボードやカラムが消えていたら黙って既定（開いているボードの先頭カラム）に戻す
- **開いていないボードへのキャプチャは Undo の対象にしない。** Undo のスタックは開いているボードのモデルが持つもので、開いていないボードの操作を積む場所がない。積める場所を作ると「Undo を押したのに画面が変わらない」状態を作ることになる
- **自動バックアップの世代は「起動ごと」ではなく「1 日ごと」に刻む。** ファイル名に日付を入れ、その日のファイルが既にあれば取らない。起動ごとに刻むと、壊したあとに何度か起動し直しただけで無事だった世代が押し出されて消え、バックアップが一番要る場面でローテーションが正本を食う。日付で刻めば、同じ日に何度起動しても残るのはその日の最初の 1 回（＝まだ壊していない状態）になる。「前回から変わったか」を持ち回る状態も要らず、ファイルの有無だけで決まる（[ADR 0003](adr/0003-daily-backup-generations.md)）
- **控えを取るのは起動時で、終了時ではない。** 終了時に取ると、壊した状態のほうを保存することになる。書き込みは `.part` に対して行い、完了してから `rename` する。途中でアプリが終わっても、中途半端なファイルが世代として残らない
- **控えが守るのは人的ミスとアプリのバグまで。** `backups/` はデータベースと同じディレクトリにあるので、ディスク障害や誤ったディレクトリ削除からは守れない。持ち出し先の管理を始めるとクラウド同期の設計になり、README の「やらないこと」に入る。境界はマニュアルに書いて、あとはユーザーのバックアップに任せる
- **確認ダイアログは Undo の代わりではない。** 出すのは「Undo で戻せない」か「1 操作で複数件が消える」ものに限る。すべての削除に出すと、読まずに押す確認になって役に立たなくなる
- **初回に見えるものに、消す前提のものを置かない。** 空のデータベースを開いたときに作るのは「やること / 進行中 / 完了」の 3 カラムだけで、カードは 1 枚も入れない（`Board::first_run`）。使い方を伝えるカードを置く案もあるが、読み終わったら消すものを最初に置くのは、消す手間を全員に配ることになり、消したあともアーカイブか `card_events` に残る。カラムだけは置く。0 カラムだと最初にやることが「カラムを作る」になり、Kanban の形が伝わらない
- **初回のシードとテストの土台を同じ関数にしない。** `Board::first_run()`（production）と `Board::fixture()`（`#[cfg(test)]`）に分ける。1 つが両方を兼ねていたころは、初回の見た目を直すつもりで中身を変えるとテストが壊れた
- **説明に貼られた URL は、入力欄の中でリンクとして描く。** 説明はプレーンテキストのままにする（「やらないこと」の Markdown の描画）ので、解釈するのは `http(s)://` だけ。見出しも強調も記法も見ない（[ADR 0002](adr/0002-links-inside-the-description-field.md)）
- **そのために説明欄はコードエディタのモード（`EditorState`）で持つ。** 色を付ける口（`InputHighlighter`）もクリックの当たり判定（`DefinitionProvider`）も、`gpui-base` ではコードエディタのモードにしか無い。ふつうの複数行入力（`TextareaMode`）は `type Extras = ()` で、置き場所が無い。行番号・折りたたみ・検索は切ってあり、コードとして扱っているわけではない
- **開くには修飾キーを要求する。** 素のクリックは「そこにカーソルを置く」という編集の意味を既に持っている。`Cmd` / `Ctrl` + クリックにするのは、それを壊さないため
- **リンクとして拾うのは `http://` と `https://` だけ。** 裸の `example.com` や `ftp://` まで拾うと、URL でない文字列がリンクになる。末尾の句読点と閉じ括弧は落とすが、`)` は対応する `(` が URL の中にあるときだけ残す
- **入力欄の初期値に、案内の文言を入れない。** 案内は placeholder で出す。既定値として入れると、消し忘れがそのままデータになる。「+ カードを追加」が説明に「説明を追加してください」と書いたカードを作っていた（#36）。任意の項目はその旨も placeholder に書く
- **新しいカードは、保存されるまで足さない。** 追加した時点では SQLite に書かず、タイトルが入って保存が通ってから書く。キャンセルされたらカードごと取り下げる（`discard_added_card`）。取り下げは削除ではないので `card_events` に `deleted` を残さず、Undo にも積まない。使う人から見れば、そのカードは一度も存在していない。タイトルは必須なので、これをやらないと無題のカードが残る経路ができる
- **1 行の入力欄では `Enter` で確定する。** カードのタイトル、カラム名、タグ名、検索のように改行の要らない欄は `Enter` で保存し、`Escape` で取り消す。打ち終わりに保存ボタンへ手を伸ばさせない。複数行の欄（カードの説明）では取らない。改行のほうが要るため、カードの編集パネルでも `Enter` を拾うのはタイトル欄の中だけにする
- **常用しない操作を画面に常時出さない。** カードの操作は右クリックメニュー、カラムの操作は `…` メニュー、タグの追加・編集・削除はメニューから開くタグ整理パネルに集約する。`danger`（赤）はダイアログの確定ボタンとメニュー内の削除項目だけに使う
- **ネイティブのメニューバーが無い環境では、同じ項目を画面内のメニューに出す。** `cx.set_menus` が効くのは macOS だけで、Linux と Windows では何も出ない。そこでメニューに畳んだ操作が消えると、画面に常時出す以外に手が無くなり、上の決まりごとが守れなくなる。ヘッダの `≡` から出すこのメニューは macOS では出さない。ネイティブのメニューバーと二重になるだけで、たどれる操作は増えないため。項目の定義は `src/menu.rs` にメニューバーと並べて置き、押したときはメニューバーと同じアクションを投げる。操作の実体を二重に持つと、経路によって挙動がずれる（[ADR 0005](adr/0005-in-app-menu-without-a-menu-bar.md)）
- **期限では絞り込まない。** 期限は表示するだけで、絞り込みの条件にしない。使い道が無かったので #32 で外した。絞り込みの条件は検索とタグの 2 つに保つ
- **カード番号へは検索欄から辿る。** 検索欄に `#` と数字だけを打ったときは、その番号のカードだけを残す。`#イベント` のような数字でない語は番号として読まず、文字列検索に落ちる。番号を指定して開く別のコマンドは持たない。入力の場所が検索欄と 2 つに割れるため（[ADR 0008](adr/0008-reaching-a-card-by-its-number.md)）
- **タグでの絞り込みはカード上のタグチップから行う。** ヘッダにタグを一覧しない。タグが増えるほどヘッダが混み、絞り込みたいタグはたいてい目の前のカードに付いている。ただし絞り込み中はヘッダにそのタグを 1 つだけ出す。減光の理由が画面から読めなくなると、なぜこのカードが暗いのかを答えられなくなるため
- カード表面の高さは、チェックリストの項目数のような可変の要素で変えない。ドラッグゴーストの大きさと挿入位置の判定が安定しなくなるため
- **画面の振る舞いは、本物のウィンドウを開いて確かめる。** GPUI のヘッドレステスト（`#[gpui_kit::test]`）でアクションとキー入力を流し、画面の状態と SQLite に書かれた内容の両方を見る。純粋関数に切り出して単体で確かめるだけでは、`render` の配線（`on_action` の付け忘れ、`key_context` の取り違え、入力欄にフォーカスがある間の抑止）が抜けても気づけない。切り出し自体は続けるが、それはテストの代わりにはならない
- **テストの待ち合わせは `run_until_parked()` で書く。** テストの時計は偽物なので実時間の `sleep` は当てにならず、入れると保存の完了を待たないテストが偶然通るようになる

## スコープ外

README の「やらないこと」のとおり、実装しません。

- クラウド同期、アカウント、サーバー通信
- 複数ユーザー、共有、権限管理
- 通知・リマインダー（期限は表示のみ。OS 通知は扱わない）
- Markdown レンダリング（説明はプレーンテキストのまま）
- 他ツールからのインポート（ID 衝突と重複解決が実質的に同期の設計になるため）

## 検討して入れないと決めたもの

Trello と OmniFocus を参照して洗い出した候補のうち、検討のうえ実装しないと決めたものです。「思いつかなかった」のではなく「判断した」ことを残すために書いています。

| 項目 | 判断の理由 |
| --- | --- |
| 開始日（`defer_date`） | Kanban では「まだ着手しない」を**カラムが表している**。Backlog / Someday というカラムがあるのに日付でも同じことを表すと状態の表現が二重になり、「Ready カラムにあるが開始日が来ていないカード」が何を意味するのか答えられない。減光の条件を増やすと「なぜこのカードが暗いのか」が読めなくなる（期限での絞り込みを #32 で外したので、今の条件は検索とタグの 2 つ） |
| 保存されたビュー（Perspective） | 個人の 1 ボードでタグ数個・カラム数個の規模なら、絞り込みを手で作り直すコストはそもそも低い。ヘッダを混ませない方針とも合わない（#31 でタグ一覧を、#32 で期限の絞り込みをヘッダから外した）。OmniFocus の Perspective が効くのはプロジェクト数百のスケールがあってこそ |
| フラグ（1 bit の重要マーク） | タグで完全に代用できる。欲しくなる理由は操作コストなので、カードのコンテキストメニューでタグを直接トグルできるようにして解決した |
| カードの複数選択 | 主用途である「Done をまとめて片付ける」は `archive_column` ですでに満たされている。複数選択の D&D はゴーストの見せ方と挿入枚数の表現が難しく、最重視の D&D の直感性を落とすリスクが実利に見合わない |
| カラムの折りたたみ | 折りたたんだ列への D&D の振る舞い（落とせないのか、ホバーで展開するのか、末尾固定で落とせるのか）がどれも今の一貫性から外れる。カラム 3〜5 個の現状では横スクロールに困っておらず、困っていない問題への対処になる |
| 見積ポイントと WIP のポイント制 | 個人ボードで見積の運用は続きにくく、空欄のまま放置されてポイント制が機能不全になる。枚数の粗さはむしろ「大きすぎるカードは分割しろ」という圧力として働く。加えて `card_events` が入ったので**実測のサイクルタイム**が取れる。見積は実測の代替なので、実測が取れるなら要らない |
| 添付ファイル・カバー画像 | ローカル専用なので絶対パスを持つだけで実装できるが、ファイルが移動・削除されたときの破綻の面倒を見る価値がこのアプリにはない |
| カレンダー / タイムラインビュー | D&D の落とし先がボードとカレンダーで二重になり、最優先の方針と正面から衝突する |
| コメント欄・アクティビティフィード | 単独ユーザーでは薄い。「いつ何が起きたか」は `card_events` が持つ |
| 2 つ目の起動から既存ウィンドウを前に出す | 動いているプロセスに「前に出ろ」と伝える経路（Unix ドメインソケット、D-Bus など OS ごとに違う仕組み）が要る。それは URL スキームの受け口と実質同じもので、URL スキームを保留にしている理由そのもの。片方だけ先に作ると、あとで二重の仕組みになる。2 つ目は理由を出して終了するに留める |
| アプリ内からの控えの復元 | 世代を選んで差し替える UI を作ると、開いているボードの破棄、保存中の待ち合わせ、失敗時のロールバック、Undo スタックの扱いが要る。戻す作業は年に数回で、そのために常時抱える複雑さに見合わない。控えはデータベースと同じ形式の 1 ファイルなので、アプリを終了してファイルを上書きすれば戻る。手順は `docs/MANUAL.md` に書いた |
| メニューバー常駐（ステータスバーアプリ） | 常駐の価値はクイックキャプチャと通知にあるが、前者は常駐なしの小窓として実装する方針にしたため常駐は要らず、後者はスコープ外。残るのは「ウィンドウを速く出す」だけで、Dock と `Cmd+Tab` で足りている。「アプリが起動している間しか効かない」が実際に不満になったら、そのときに再検討する |

## 変更の完了条件

issue を閉じる前に、すべて満たしていること。

1. `cargo fmt --all -- --check` が通る
2. `cargo clippy --all-targets --all-features -- -D warnings` が通る
3. `cargo test --all-features` が通る
4. モデルの変更には `#[cfg(test)]` のユニットテストが付いている

7. 入力欄を追加・変更した場合は、日本語 IME での入力を実機で確認している
8. 表示を変更した場合は、macOS のライトとダークの両方で確認している
