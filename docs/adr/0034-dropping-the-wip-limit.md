# 0034. WIP 上限をやめる

- 日付: 2026-09-07
- 状態: 有効

## 状況

カラムには WIP 上限（`columns.wip_limit`）があり、カラムのヘッダに `2 / 2` と
出して超過したら赤くしていた。上限は「編集」から数字で入れ、空欄で「上限なし」
にできた。

この仕組みは、複数人のチームで**他人に見せる約束**として働くものです。着手中の
枚数を絞ることに合意した相手がいて、超過が目に入れば誰かが引き取る。そこが
効きどころでした。

このアプリはローカル専用の 1 人用ボードです（[スコープ外](../DESIGN.md#スコープ外)）。
上限を決めるのも、超えるのも、赤いのを見るのも同じ 1 人になります。

## 決定

WIP 上限を、モデル・コマンド・画面・スキーマから消す。カラムのヘッダは枚数だけ
を出す（`3 枚`）。`set_column_wip_limit` コマンドと `Field::WipLimit` を消し、
カラムの「編集」は名前だけの欄にする。`columns.wip_limit` の列と索引は
スキーマ移行 11 で落とす。

## 理由

守らせる相手が自分しかいない警告は、守られないときに 2 つの逃げ道しか残しません。
上限のほうを上げるか、赤いまま無視するか。どちらを選んでも、次からその赤は何も
意味しなくなります。**意味を失った警告が画面に残り続けるほうが、警告が無いより
悪い**——他の赤も同じ重さで読まれなくなるからです。

「着手中が多すぎる」を知る手段は、消しても残ります。枚数はヘッダにそのまま出て
いて、カラムは横に並んでいるので、多いカラムは見れば分かります。上限という数字
は、その判断を前もって 1 つの整数に押し込めるものでしたが、押し込めた先に
機能する強制力がありません。

消す範囲を「画面から隠す」ではなく列ごと落とすところまでにしたのは、
[スキーマ移行 10](../../crates/core/src/db/mod.rs)（期限の絞り込みの保存値を消した
もの）と同じ理由です。読まれない列を全ユーザーのデータベースに置いたままにすると、
次に `columns` を触る人がそれを生きている列だと読みます。

## 採らなかった案

- **上限を残し、警告だけ弱める（色を消して数字だけにする）。** `2 / 2` の分母は、
  読む人に「何かの決まりがある」と伝えます。強制力の無い決まりを表示だけ残すのは、
  いちばん中途半端な形になります。
- **列を残してコードだけ消す。** 移行を書かずに済みますが、次にスキーマを読む人
  への嘘が残ります。SQLite に `DROP COLUMN IF EXISTS` は無いので、移行では
  `pragma_table_info` で有無を見てから落とします。
- **実測のサイクルタイムで置き換える。** `card_events` から出せますが、これは
  WIP 上限とは別の機能で、別の issue で判断するものです。上限を消す理由が
  「代わりが要る」ことに変わってしまいます。

## 結果

カラムのヘッダが枚数だけになり、カラムの「編集」は 1 欄になりました。
`BoardOperation::SetColumnWipLimit` が消えたので Undo の対象も 1 つ減りました。

引き受けた不都合として、上限を設定していた古いデータベースでは、その数字が移行の
時点で失われます。控え（`docs/MANUAL.md`）には移行前のファイルが残りますが、
アプリから読み直す手段はありません。1 人用のボードで、失われるのが「自分で決めた
上限」であることを踏まえて、移行前に控えを取る以上のことはしません。
