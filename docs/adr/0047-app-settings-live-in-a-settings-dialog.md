# 0047. アプリ全体の設定は設定画面に置く

- 日付: 2026-09-09
- 状態: 有効
- 関連: #196、[ADR 0027](0027-creating-tags-while-editing-a-card.md)、[ADR 0030](0030-capturing-a-shortcut-needs-the-menu-out-of-the-way.md)

## 状況

設定が 3 か所に散っていた。

- テーマ — 「表示」メニューの 3 項目
- クイックキャプチャの割り当て — macOS はアプリメニュー、ほかはヘルプメニュー →
  `ShortcutDialog`
- クイックキャプチャの入れ先 — カラムの `…`

どれも「アプリ全体のもの」で、開いているボードとは関係がない。それが 3 か所に
あるので、**何を変えられるのかを知る場所が無い**。使う人は、割り当てを変えたい
たびに「あれはどのメニューだったか」を思い出すことになる。

ここに「日付の切り替わり時刻」が 4 つ目として加わる。置き場所を決めずにもう
1 つ足せば、散り方が固定される。

決めるべきことは 2 つあった。**アプリ全体の設定をどこに置くか**と、置くとして
**割り当ての捕捉をどう持ち込むか**である。後者は移設ではない——[ADR 0030] の
手当て（キーを捕まえている間、OS のメニューからアクセラレータを外し、項目を
無効にする）が、専用のダイアログを前提に書かれていた。

[ADR 0030]: 0030-capturing-a-shortcut-needs-the-menu-out-of-the-way.md

## 決定

**アプリ全体のものは設定画面、開いているボードのものはパネル。**

- 設定画面は `<dialog>`（`web/src/shell/SettingsDialog.tsx`、`shell/Dialog.tsx` の
  枠を共用）。パネルにはしない
- 入り口はメニューの「設定…」1 項目、`CmdOrCtrl+,`。macOS はアプリメニュー、
  ほかは「ファイル」の末尾（閉じる・終了の上）
- 中身は 3 つ——テーマ、クイックキャプチャの割り当て、クイックキャプチャの
  入れ先（**表示のみ**）
- 保存ボタンは置かない。触った時点で確定する
- ブラウザ版で相手がいない項目（ホットキー）は消さず、欄を灰色にして理由を
  文言に入れる

**テーマのメニュー項目は残す。** 「表示」メニューの 3 項目はそのまま。

**「クイックキャプチャのショートカット…」のメニュー項目は消す。** 割り当ては
設定画面の中だけになり、`AppAction` も `setQuickCaptureShortcut` から
`openSettings` に変わる。

**メニューのアクセラレータは、設定画面が開いているあいだずっと外す。**
[ADR 0030] は「割り当てを捕まえている間」と書いていたが、捕まえる欄に焦点が
あるあいだだけ、にはしない。

## 理由

**パネルは、開いているボードを編む場所である。** タグ整理パネルが扱うのは
そのボードのタグで、繰り返しの定義はカラムとタグを参照する。そこにアプリ全体の
設定を混ぜると、「どのボードの設定なのか」が画面から読めなくなる。設定はボードに
紐づかないので、ボードの脇に開く板ではなく、盤面の上に出るダイアログにする。

**切り替える場所と、いま何かを見る場所は別でよい。** テーマのメニュー項目を
残すのは、1 クリックで切り替わることに値打ちがあるからで、設定画面が引き受ける
のは「いまどれが選ばれているか」を読めることのほうである。タグを作れる場所が
2 か所あるのと同じ形で（[ADR 0027]）、役割が違うものは 2 か所にあってよい。

**入れ先だけは残す道が無い。** 「このカラムを入れ先にする」は、そのカラムを
指す操作である。設定画面から選ぶには、ボードとカラムを 2 段で選ばせる仕掛けを
別に作ることになり、カラムの `…` から 1 回で済んでいたものが遠くなる。だから
設定画面には、いまどこなのかを出すだけにする。

**割り当ての入り口は 1 つにする。** メニュー項目を残したまま設定画面にも置くと、
同じ捕捉が 2 か所から開く。捕捉は [ADR 0030] の手当てを背負っている部分で、
2 つあれば片方だけ直る日が来る。

**アクセラレータを外す範囲を広げるのは、隙間を作らないため。** 焦点の移動は
同期だが `set_menu_accelerators_active` は Rust への往復で、欄に焦点が移った
直後の 1 打はまだメニューが割り当てを持っている。[ADR 0030] が直したのは
まさに「押したのに `keydown` が届かない」で、狭く取ると同じことが小さく
戻る。設定画面が開いているあいだ、盤面のアクセラレータには届く先が無いので、
広く外して失うものが無い。

**`CmdOrCtrl+,` は 3 つの OS で設定を開くキーである。** muda は `,` も
`Comma` も同じ `Code::Comma` に読むので、書き方は `,` に決めた
（`web/src/shell/menu.ts`）。webview 側の割り当ての読み取り
（`web/src/shell/accelerator.ts`）は英数字とファンクションキーしか読めなかった
ので、記号を 1 つずつ足せる形にした。

[ADR 0027]: 0027-creating-tags-while-editing-a-card.md

## 採らなかった案

- **設定もパネルにする。** 右の板は 1 つで、開くとタグ整理パネルと場所を
  取り合う。それ以上に、パネルは「開いているボードを編む場所」という読み方が
  できあがっている。ボードに紐づかないものを同じ板に出すと、その読み方が崩れる。
- **メニューの「表示」からテーマの 3 項目を落とし、設定画面だけにする。**
  1 クリックで切り替わるのをやめて、ダイアログを開かせることになる。テーマは
  設定の中でいちばん頻繁に触るもので、遠くする理由が無い。
- **「クイックキャプチャのショートカット…」をメニューに残す。** 入り口が
  2 つになる。上記のとおり、捕捉は 2 か所に持たせたくない。
- **入れ先を設定画面から選べるようにする。** ボードとカラムを選ぶ仕掛けを
  別に作ることになり、カラムの `…` にあるものと合わせて 2 か所になる。
  「そのカラムを指す」操作は、そのカラムの上にあるのがいちばん短い。
- **アクセラレータを外すのは、捕捉の欄に焦点があるあいだだけにする。**
  範囲としては正しいが、焦点の移動と往復の間に隙間ができる（上記）。
- **`ShortcutDialog` をそのまま残し、設定画面から開く。** ダイアログの上に
  ダイアログが重なる。設定を見に来た人が、割り当てを見るのにもう 1 枚開く
  ことになり、畳んだ意味が無い。

## 結果

アプリ全体の設定が 1 か所になり、4 つ目（日付の切り替わり時刻）の置き場所も
決まった。散っていた 3 つのうち、割り当ては設定画面に畳まれ、テーマは
メニューと設定画面の両方から、入れ先はカラムの `…` から触れる形で残った。

引き受けた不都合は 2 つある。

- **テーマを変えられる場所が 2 か所になった。** どちらも同じ `setTheme` を
  通るので食い違いはしないが、「テーマはどこで変えるのか」の答えが 1 つでは
  なくなった。
- **割り当ての捕捉が、ダイアログ全体ではなく 1 つの欄になった。** キーを受ける
  のはその欄に焦点があるあいだだけなので、焦点がどこにあるかが画面から読める
  必要がある（枠の色と「キーを受け付けていません」の文言がそれ）。専用の
  ダイアログだったころは、開いていること自体がその合図だった。
