# 0008. カード番号へは、検索欄に `#12` と打って辿る

- 日付: 2026-09-05
- 状態: 有効
- 関連: #60

## 状況

編集パネルはカード番号（`#12`）を出しているのに、その番号を使って目的のカードへ辿り着く手段が無かった。検索が見るのはタイトルと説明だけで、番号を指定して開くコマンドも無い。

番号を見せているのは、外から指せるようにするためのはずだった。[`docs/DESIGN.md`](../DESIGN.md) の「前提が揃えば検討するもの」にある URL スキーム（`ekanban://board/1/card/12`）はその受け口だが、既に起動しているアプリへ URL を渡す単一インスタンス制御が要るため保留にしてある。

保留のあいだ、番号は「見えるが辿れないもの」として置かれ続けていた。

## 決定

検索欄に `#` と数字だけを打ったときは、その番号のカードだけを残す。`#` のうしろが数字でないもの（`#イベント`）は番号として読まず、これまでどおりの文字列検索に落ちる。

絞り込みの見せ方は既存と同じで、ほかのカードは隠さず減光する。

## 理由

**アプリの中で番号から辿るだけなら、URL スキームの前提は要らない。** 単一インスタンス制御が必要なのは「外からアプリへ渡す」ためであって、既に開いている画面の中で番号を指すためではない。保留の理由と、この不満は同じものではなかった。

**絞り込みの条件は増えていない。** `docs/DESIGN.md` は「絞り込みの条件は検索とタグの 2 つに保つ」としている。番号は検索欄の中の書き方であって、3 つめの条件ではない。ヘッダに新しい入力欄も増えない。

**`#` + 数字は衝突しにくい。** タイトルに `#12` と書く使い方はありうるが、そのカードを探している人が `#12` と打つのは、たいてい番号のほうを指している。番号でない `#` 付きの語（`#イベント`）は数字で始まらないので、判定が食い違わない。

## 採らなかった案

- **番号を指定して開くコマンド（パレット / メニュー項目）を足す。** 入力の場所が検索欄ともう 1 つに割れる。「カードを絞り込む」という同じ目的に対して入口を 2 つ持つことになり、`docs/DESIGN.md` の「常用しない操作を画面に常時出さない」とも噛み合わない。
- **番号でも文字でも当たったものを残す（和集合にする）。** タイトルに `#12` を含む別のカードまで残る。番号で探しているときに 1 枚に絞れないなら、番号で探せるようにした意味が薄い。
- **URL スキームを先に作る。** 単一インスタンス制御は「2 つ目の起動から既存ウィンドウを前に出す」と同じ仕組みで、`docs/DESIGN.md` はそれを入れないと決めている。この issue のために先に作ると、判断の順序が逆になる。
- **番号のカードまでスクロールして選択する。** ほかの絞り込みと振る舞いが変わる。検索は減光する、番号だけスクロールする、では検索欄の中で挙動が二重になる。

## 結果

番号から辿れるようになり、番号を見せている理由が画面の中で完結した。

引き受けたのは、タイトルが `#12` で始まるカードを文字として探せなくなること。`#` を外して `12` と打てば文字としての検索に戻るので、逃げ道は残っている。

URL スキームの保留は解いていない。外から指す話は前提が変わっていない。
