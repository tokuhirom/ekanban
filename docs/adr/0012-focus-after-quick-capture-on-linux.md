# 0012. クイックキャプチャを閉じたあとの行き先は、Linux では 1 つだけ保証する

- 日付: 2026-09-05
- 状態: 有効
- 関連: #52

## 状況

マニュアルは、クイックキャプチャを `Enter` でも `Escape` でも閉じたあと「フォーカスは直前のアプリに戻ります」と書いていた。Linux ではそうならない。

`restore_focus_after_capture` が使っている `App::hide` と `App::activate` は、`gpui-pre-linux` の `platform.rs` でログを出して戻るだけになっている。

```rust
fn activate(&self, _ignoring_other_apps: bool) {
    log::info!("activate is not implemented on Linux, ignoring the call")
}
fn hide(&self) {
    log::info!("hide is not implemented on Linux, ignoring the call")
}
```

`on_quick_capture` の冒頭の `cx.activate(true)` も同じなので、ボードのウィンドウが後ろにいるときに前へ出てこない。

「動くはずのものが動かない」状態が、マニュアルの記述として残っていた。

## 決定

2 つに分ける。

- **ボードのウィンドウへ戻す**（ホットキーを押したとき ekanban が前面だった場合）は、ウィンドウ単位の `Window::activate_window` で行う。X11 実装は `_NET_ACTIVE_WINDOW` を投げるので効く。そのためにキャプチャウィンドウへボードのウィンドウハンドルを持たせる
- **直前のアプリへ返す**（ほかのアプリを使っている途中だった場合）は、Linux では ekanban 側で決めない。キャプチャウィンドウが閉じたあとの行き先はウィンドウマネージャに任せる

マニュアルのショートカットの説明を OS 別の表に書き分け、Linux の 2 つ目は「ekanban 側では決められない」と書く。

## 理由

**片方は直せる。** アプリ全体を前に出す API が無いだけで、ウィンドウを前に出す API はある。直せるほうを「Linux では無理」の側に混ぜない。

**もう片方は直せない。** 直前のアプリへ返すには、自分を隠すか、相手を名指しで前に出すかのどちらかが要る。gpui の Linux 実装に前者は無く、後者はそもそもどのアプリだったかを知る手段が無い。X11 の `_NET_ACTIVE_WINDOW` は自分の窓にしか投げられない。

**書けないことは書かない。** 動かないものを「動きます」と書いてあると、動かなかった人は自分の環境を疑う。「ここは決められない」と書いてあれば、疑う先が正しくなる。`docs/DESIGN.md` の「Wayland ではウィンドウの位置を復元しない」も同じ形で、直せないものを直せるように見せていない。

**X11 でも WM に阻まれうる。** フォーカス強奪防止の設定によっては `activate_window` が効かず、代わりにタスクバーが点滅する構成もある。それでも「効くこともある」ほうが「必ず何も起きない」よりよく、効かないときの見え方は WM の設定どおりで説明できる。

## 採らなかった案

- **キャプチャを開く前に前面だったウィンドウを覚えておいて、閉じるときに戻す。** X11 では他アプリのウィンドウ ID を取ること自体はできるが、それを前に出すのは他アプリのウィンドウの操作で、gpui の外に降りる話になる。ウィンドウマネージャごとの差も大きく、1 行のキャプチャのために持つ複雑さではない。
- **`cx.hide()` の代わりにボードのウィンドウを最小化する。** ボードが後ろにいるだけのときまで最小化してしまう。押す前より状態が悪くなる。
- **Linux ではマニュアルの記述だけ直して、コードは触らない。** ボードへ戻すほうも直らないままになる。直せるものを直さない理由がない。
- **`gpui-pre-linux` に `activate` を実装して上流へ出す。** アプリ全体という単位が X11 に無いので、実装しても「最後に触った自分のウィンドウを前に出す」程度になる。それはこちらで `activate_window` を呼ぶのと同じことで、依存側を先に直す理由がない。

## 結果

Linux でも、ボードが後ろにいるときにキャプチャを閉じればボードが前に出るようになった。

引き受けたのは、閉じたあとの行き先が OS で違うこと。マニュアルに OS 別の表で書いた。

`activate_window` が X11 のフォーカス強奪防止に阻まれるかどうかは、実機で確かめるしかない。ヘッドレスのテストでは、テスト用プラットフォームの `activate_window` が何もしないため確かめられない。
