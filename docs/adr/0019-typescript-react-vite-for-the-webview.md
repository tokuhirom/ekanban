# 0019. 画面は TypeScript + React + Vite で作る

- 日付: 2026-09-06
- 状態: 有効
- 関連: #97、[0017](0017-moving-the-ui-to-tauri.md)

## 状況

[0017](0017-moving-the-ui-to-tauri.md) で webview へ移ると決めたが、webview の中を何で書くかは決めていない。Tauri は中身を選ばない（素の HTML でも動く）ので、ここは別の判断になる。

移る理由に挙げたのは 3 つで、**部品の質**・**供給の安定**・**標準の道具（テストと支援）**だった。中で使うものを選ぶときも、同じ 3 つで測るのが筋が通る。

## 決定

**TypeScript + React + Vite にする。** 状態の管理に専用のライブラリは入れない。

- スナップショットは 1 か所で保持し、コマンドを呼んで差し替える経路も 1 本にする（[0018](0018-rust-owns-the-board-state.md)）。React の標準の仕組みで足りる
- 型は `ts-rs` で Rust から生成する。手で 2 か所に書かない
- CSS はカスタムプロパティでトークンを定義し、`ActiveTheme` の色の規則をそのまま移す。CSS フレームワークは入れない
- ネットワークから読むもの（web フォント、CDN）は使わない

## 理由

**部品がいちばん多いから。** チップ列＋補完付きのタグ入力、日付入力、ダイアログ——移行の動機になった [#89](https://github.com/tokuhirom/ekanban/issues/89) [#90](https://github.com/tokuhirom/ekanban/issues/90) [#91](https://github.com/tokuhirom/ekanban/issues/91) は、どれも既製品で解ける領域である。既製品の厚みは React がいちばんある。

**AI の習熟度がいちばん高いから。** [0017](0017-moving-the-ui-to-tauri.md) は「gpui は学習データが薄く、フォークごとに API が違う」ことを移る理由の 1 つに挙げた。その基準で選ぶなら、web の中でも学習データが最も厚いものを選ぶのが一貫している。

**供給が安定しているから。** フォークが 4 系統に割れている状況から逃げてきたので、単一の実装に人生を賭けない形を選ぶ。

**状態管理を足さないのは、持つ状態が少ないから。** 盤面は Rust にあり、webview が持つのは下書きと表示の状態だけ。ここにライブラリを 1 つ足すと、その API の癖がテストにも波及する。要るとわかってから足す。

## 採らなかった案

- **Svelte / SolidJS。** 書き味は良く、成果物も小さい。選ばなかったのは学習データの厚みで、それは gpui を離れる理由そのものだった。同じ理由で 2 度目の代償を払うことになる
- **素の HTML と TypeScript（フレームワーク無し）。** 依存は最小になるが、いま自作を避けたくて移っているのに、差分描画とコンポーネントの合成を自作することになる。「作りたいのは Kanban であって UI ツールキットではない」に反する
- **CSS フレームワーク（Tailwind など）を入れる。** 色の規則（[`docs/DESIGN.md`](../DESIGN.md)）はトークンで表すのがいちばん素直で、その上に別の語彙を重ねると、規則の在り処が 2 つになる
- **状態管理ライブラリ（Zustand / Redux など）を入れる。** 持つ状態が少ないので、いまは要らない

## 結果

得るもの。入力欄の質が既製品の水準から始まる。AI 支援の効きが戻る。テストの道具（Vitest / Playwright / Testing Library）が最初から揃っている。

引き受ける不都合。

- 依存の本数が増える。Rust 側で `cargo` 1 つに保っていたものが、`npm` のロックファイルも見る形になる
- ビルドに Node が要る。CI もリリースも、この分だけ長くなる
- `unsafe_code = "forbid"` の担保が Rust 側にしか効かない。TypeScript 側は `tsc --strict` と ESLint で代える
- React の作法（再描画の単位、キーの付け方）を間違えると、D&D の追従が落ちる。[0020](0020-pointer-based-drag-and-drop.md) の受け入れ条件で確かめる
