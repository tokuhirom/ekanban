# 0036. モデルは 1 つ、置き場所は 2 つ

- 日付: 2026-09-07
- 状態: 置き換えられた（→ [0042](0042-the-browser-build-is-the-same-typescript.md)）
- 関連: [0018](0018-rust-owns-the-board-state.md)、[0021](0021-two-layer-testing-for-the-webview.md)、[0035](0035-a-browser-build-of-the-real-core.md)

## 状況

[0035](0035-a-browser-build-of-the-real-core.md) で、中核を `wasm32-unknown-unknown` に組み直してブラウザで動かすことにした。最初の実装は **SQLite ごと**持っていった——`rusqlite` は wasm を対象にすると `sqlite-wasm-rs` を通すので、`db/mod.rs` を 1 行も変えずに動いた。

**動いたが、重かった。** 測った値がこれである。

| | 生 | gzip |
| --- | --- | --- |
| wasm 全体 | 2,497,736 | 912,918 |
| **`rusqlite` を開くだけの空クレート** | **2,107,281** | — |

**2.5 MB のうち 2.1 MB が SQLite**で、こちらのコード全部（`model.rs`・`db/mod.rs`・`commands.rs`・serde・chrono）は 400 KB に収まっていた。gzip で配って、盤面が出るまでの時間はこうなった（Chromium、帯域を絞って計測）。

| 回線 | 盤面が出るまで |
| --- | --- |
| 帯域制限なし | 0.55 秒 |
| 10 Mbps | 1.8 秒 |
| Fast 3G (1.6 Mbps) | 7.2 秒 |

しかも、その間は白い画面である。**「入れずに試せる」ために作ったものが、いちばん試しにくい入り口になっていた。**

`sqlite-wasm-rs` が有効にしている FTS5・RTREE・SESSION・PREUPDATE_HOOK は、このアプリが 1 つも使っていない。だが、その組み合わせはあちらの `build.rs` にあり、こちらから絞れない。

## 決定

**置き場所を差し替えられるようにし、ブラウザでは SQLite を積まない。**

- `crates/core/src/store.rs` に `Store` を置く。`crates/app` の `commands` はこれだけを見て、下にいるのがどちらかを知らない
- 配るアプリは今までどおり `db::Database`（SQLite）。**ブラウザは `JsonStore`**——`Board` を serde で JSON にして、文字列 1 つを `localStorage` に置く
- `crates/core` に `sqlite` feature（既定で有効）を足し、`db` と `backup` をその内側に置く。`crates/app` の `shell` がそれを引く
- **`model.rs` は分けない。** 採番も並べ替えも Undo もアーカイブもタグも 1 つのままで、分かれているのは「どう置くか」だけ
- 書き出す JSON の組み立ては `export::render_board_json` の 1 か所にする。置き場所から受け取るのはカードの履歴だけ

結果、wasm は **879,102 バイト（gzip 251,345）** になった。**生で 65%、gzip で 72% 減**で、React のバンドルと同じ桁である。盤面が出るまでの時間も、同じ測り方でこうなった。

| 回線 | 前 | 後 |
| --- | --- | --- |
| 帯域制限なし | 0.55 秒 | **0.30 秒** |
| 10 Mbps | 1.8 秒 | **0.72 秒** |
| Fast 3G (1.6 Mbps) | 7.2 秒 | **3.6 秒** |

3G の 3.6 秒はまだ長いので、**読み込み中の表示を出す**——`demo/index.html` に置いた 1 行を React が差し替える。白い画面のままにしない。

## 理由

**重さの原因が SQLite だったため。** 「wasm だから重い」ではなかった。こちらのコードは 400 KB で、置き場所を差し替えれば、それだけが残る。

**モデルを 2 つにしないため。** 素直な代案は「ブラウザ版は TypeScript で `Ipc` を実装する」だが、その裏側は測ったところ **約 5,200 行**あった（`model.rs` 2,588・`db/mod.rs` 1,370・`commands.rs` 795・`snapshot.rs` 212・`state.rs` 203）。採番、reindex、Undo / Redo、検索の全角半角の正規化、期限の読み取り、期限件数つきのボード一覧。**いまそれを守っているのは Rust のテストで、TypeScript の写しには掛からない。** [0021](0021-two-layer-testing-for-the-webview.md) が「偽物は必ず本物からずれる」と決めた理由がそのまま当てはまる。

**分けたのが置き場所だけなら、ずれる余地が小さいため。** ここで 2 つになったのは「`Board` をどう書き出し、どう読み戻すか」であって、盤面の判断ではない。しかも SQLite 側は既にあり、テストも付いている。

**口が狭かったため。** `commands` が `Database` に呼んでいたのは 22 個で、そのうち 12 個は付随する表示の状態（最後に開いたボード、絞り込み、テーマ）の読み書きだった。盤面そのものは、読む・書く・作る・消す・一覧・履歴の 6 つしかない。

## 採らなかった案

- **SQLite ごと持っていく（最初にやったこと）。** `db/mod.rs` をそのまま使えるのが利点で、実際に動いた。**2.1 MB を毎回配ることになる**ので採らない。**スキーマ移行をブラウザで通せないことは実害にならない**——移行すべき既存のデータベースが、そこには無い
- **SQLite を絞って組み直す。** `SQLITE_OMIT_*` で FTS5 や RTREE を落とせば減る。`sqlite-wasm-rs` の `build.rs` にある組み合わせをこちらから変える道は、`links` の上書きで自前の `libsqlite3.a` を用意することだけで、**CI に手組みのビルドを 1 つ増やす**。減る量も、置き場所ごと外すほうが大きい
- **TypeScript で `Ipc` を実装する。** 読み込みはいちばん速い（wasm ゼロ）。約 5,200 行の 2 つ目の実装を持ち、`model.rs` を触るたびに追従させることになる。[0021](0021-two-layer-testing-for-the-webview.md) を覆すことになるので採らない
- **読み込み中の表示を入れて済ませる。** いちばん安い。白い画面ではなくなるが、10 Mbps で 1.8 秒・3G で 7 秒はそのまま残る
- **OPFS / IndexedDB の VFS に載せる。** SQLite を積む前提が変わらないので、大きさの問題が残る

## 結果

得るもの。ブラウザ版が **879 KB（gzip 251 KB）** になり、**モデルは 1 つのまま**である。副産物として、`crates/core` が「SQLite に依存しない層」を持っていることが feature の形で確かめられるようになった（`cargo build -p ekanban-core --no-default-features`）。

引き受ける不都合。

- **置き場所が 2 つになった。** 同じ振る舞いを 2 か所で保つ仕事が増える。狭く保つ（`Store` に盤面の判断を書かない）ことを条件にする
- **ブラウザ版に「データベースをコピー…」が無い。** 写す SQLite のファイルが無いためで、消さずに灰色にして理由を出す。**盤面の持ち出しは残る**——JSON と Markdown の書き出しがダウンロードになる
- **`localStorage` に置いた形が変わった。** 前の版（SQLite の base64）は読めない。読めないものは捨てて新しい盤面から始める。配ったのは PR の中だけなので、移行は用意しない
- **`wasm-opt` を使わなくなった。** SQLite を外してから縮むのは 1 割ほどで、binaryen を 1 つ落としてくる手間と、その版に組み立てが左右されること（手元にある古い版はこの wasm を壊す）に見合わなくなった
- **カードの履歴の番号を JSON 側でも振ることになった。** SQLite の `AUTOINCREMENT` に当たるものを `JsonStore` が持つ。書き出しの並びに出るので、1 から始めるところまで揃える
