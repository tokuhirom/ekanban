# 0013. Linux のデスクトップ統合は、`~/.local` 以下に入れるスクリプトで行う

- 日付: 2026-09-05
- 状態: 有効
- 関連: #50

## 状況

Linux の配布物（`ekanban-<版>-x86_64-unknown-linux-gnu.tar.gz`）の中身は、実行ファイルと README と LICENSE だけだった。デスクトップエントリもアイコンも入っていないので、

- アプリ一覧やランチャーに出てこない。ターミナルからパスを打って起動するしかない
- タスクバー / Dock でアイコンが汎用のものになり、名前も実行ファイル名のまま

`src/lib.rs` は `WindowOptions.app_id` に `dev.tokuhirom.ekanban` を渡している。これはデスクトップ環境がウィンドウをアプリに結びつけるための ID だが、同じ ID の `.desktop` が入っていないので結びつく先が無かった。

macOS には `.app` バンドルを作る `script/bundle-mac` と `make install` がある。Linux にはそれに当たるものが無かった。

## 決定

`assets/dev.tokuhirom.ekanban.desktop` と、`assets/icons/hicolor/<大きさ>/apps/dev.tokuhirom.ekanban.png`（16 / 32 / 48 / 64 / 128 / 256 / 512 の 7 種類）を置く。

`script/install-linux`（`make install-linux`）が、それらと実行ファイルを **XDG のユーザーディレクトリ** に入れる。

| 入れるもの | 置き場所 |
| --- | --- |
| 実行ファイル | `$XDG_BIN_HOME`（既定 `~/.local/bin`） |
| デスクトップエントリ | `$XDG_DATA_HOME/applications` |
| アイコン | `$XDG_DATA_HOME/icons/hicolor/<大きさ>/apps` |

配布物にも同じ 3 つと `install-linux` を同梱する。`--uninstall` で消せる。

アイコンは縮小済みのものをリポジトリにコミットする。ビルド時には作らない。

## 理由

**root を要求しない。** `/usr/share` に入れるには `sudo` が要る。ekanban はデータもログもユーザーのディレクトリに置く単独ユーザー向けのアプリで、システム全体に入る理由がない。`~/.local` なら、入れるのも消すのも本人だけで完結する。ディストリビューションのパッケージになる日が来たら、そのときは配布側の作法に従えばよく、その邪魔もしない。

**`Exec=` は絶対パスに書き換えてから置く。** `~/.local/bin` が PATH に入っているかは環境によって違う。エントリの中では実行ファイルの場所が分かっているので、そこを当てにする理由がない。ターミナルからも `ekanban` で呼べるようにはしたいので、PATH に無いときはその旨を出す。

**`StartupWMClass` を `APP_ID` と同じにする。** これが食い違うと、一覧から起動はできるのにウィンドウがエントリに結びつかず、タスクバーのアイコンと名前が元に戻る。同じであることは単体テスト（`the_linux_desktop_entry_points_at_the_app_id`）が見ている。片方だけ直したときに気づける場所を作るのが目的。

**アイコンは作り置きしてコミットする。** ビルド時に縮小するには、Linux のランナーに画像処理のツール（ImageMagick など）が要る。`.icns` は macOS の `sips` と `iconutil` で作れるので `make icon` で生成しているが、Linux 側で同じことをするには依存が増える。7 枚で 400KB 強なら、依存を足すより置いておくほうが安い。

## 採らなかった案

- **`/usr/share` に入れる（`sudo make install`）。** root が要る。単独ユーザーのアプリでシステム全体を触る理由がない。
- **AppImage / Flatpak / .deb にする。** どれもデスクトップエントリとアイコンを内包するので、この issue はそれで解ける。ただしビルドと配布の仕組みが 1 つ増え、更新のたびに面倒を見ることになる。まず tarball の中身を揃えるのが、いま困っていることへの最短の対処。必要になったら改めて判断する。
- **`.desktop` を実行時にアプリ自身が書き出す。** 起動しただけでユーザーのディレクトリにファイルを作ることになる。断りなく環境を変えるのは、グローバルホットキーを既定で登録しないと決めたのと同じ理由で避ける。
- **アイコンを 1 枚（1024px）だけ入れる。** hicolor のテーマは大きさごとのディレクトリで引くので、置き場所が決まらない。どこか 1 つに入れても、環境によって縮小の質が変わる。
- **ビルド時に ImageMagick で縮小する。** Linux のランナーに依存が増える。生成物が毎回変わりうるのも、配布物として扱いにくい。

## 結果

展開して `install-linux` を実行すれば、GNOME / KDE のアプリ一覧に「Ekanban」が正しいアイコンで出て、そこから起動したウィンドウがそのエントリに結びつくようになった。

引き受けたのは、アイコンをリポジトリに持つこと。`assets/icon.png` を差し替えたら 7 枚を作り直す必要がある。`docs/DEVELOPMENT.md` にそう書いた。

Windows は手つかずのまま。ショートカットとレジストリの話で、Linux とは別の作法になる。困っている人が出たら、そのときに考える。
