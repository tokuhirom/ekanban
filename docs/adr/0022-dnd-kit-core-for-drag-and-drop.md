# 0022. D&D は `@dnd-kit/core` 6 系に載せる

- 日付: 2026-09-06
- 状態: 有効（条件 8 の確かめ方は [0023](0023-verifying-the-webview-engines.md) が置き換えた）
- 関連: [0020](0020-pointer-based-drag-and-drop.md)、[0017](0017-moving-the-ui-to-tauri.md)

## 状況

[0020](0020-pointer-based-drag-and-drop.md) は「ポインタイベントで作る。既製のライブラリ（dnd-kit）に載せるのを既定とし、段階 4 の spike で受け入れ条件を確かめる。届かなければ自前に書く」と決めた。**どちらにするかは spike の結果で決める**とし、そこは開いたままにしてあった。

spike を行ったところ、dnd-kit には現在 2 つの系統がある。

| | 版 | 最終公開 | 週あたり取得数 |
| --- | --- | --- | --- |
| `@dnd-kit/core` ＋ `@dnd-kit/sortable` | 6.3.1 / 10.0.0 | 2024-12 | 約 2,490 万 |
| `@dnd-kit/react` ＋ `@dnd-kit/abstract` | 0.5.0 | 2026-09 | 約 123 万 |

前者は 21 か月更新が無く、後者は 1.0 前で活発に動いている。[0020](0020-pointer-based-drag-and-drop.md) が「gpui のフォーク乱立から逃げた先で、また 1 つ供給の不安を抱える」と書いた不安が、そのまま 2 つの形で現れている。

## 決定

**`@dnd-kit/core` 6.3.1 と `@dnd-kit/sortable` 10.0.0 に載せる。** [0020](0020-pointer-based-drag-and-drop.md) の受け入れ条件 1〜7 を WebKitGTK で満たすことを実測して確かめた。条件 8（3 つの webview で同じ）は macOS と Windows の実機が要るため、手での確認に残る。

**挿入位置の計算はライブラリの外に置く。** `web/src/board/dnd.ts` が「いま何の上にいるか」から「どこに落ちるか」を決め、`web/src/board/keyboard.ts` が矢印の割り当てを持つ。dnd-kit に渡すのは掴む・運ぶ・オートスクロールだけで、盤面の意味を決めるところは渡さない。

**キーボードは dnd-kit の `KeyboardSensor` を使わない。** いまの割り当ては修飾キーを押しながら矢印を叩く 1 手で、押している間に何枚でも動かせる。`KeyboardSensor` は掴む → 動かす → 離すの 3 手になる。

## 理由

**6 系のほうが、いま抱える不安が小さいから。** 21 か月更新が無いことは、裏を返せば**こちらの都合で壊れないこと**でもある。週 2,490 万件が取得されている以上、いまの React で動くことは分かっている。0.x は API がまだ動くので、移行の途中で追随の作業が要る側に賭けることになる。移行を終える前に版が変われば、[0017](0017-moving-the-ui-to-tauri.md) が逃げようとしたものと同じ場所に戻る。

**それでも外せる形にしてあるから、賭けが外れても戻れる。** 条件 3（オートスクロール）と条件 1（ゴースト）以外は、こちらの関数がすでに持っている。6 系が本当に動かなくなったら、その 2 つを書くだけで自前に落ちる。

**条件は下げていない。** 1〜7 を測って満たした。満たすために作り替えたのは 2 か所で、どちらもこちら側の不備だった（下記）。

## 採らなかった案

- **`@dnd-kit/react` 0.5.0。** 活発なのは良いが 1.0 前で、移行の途中に API が動くと、盤面ではなくライブラリの追随に時間を使うことになる。1.0 が出て落ち着いたら乗り換えを考える
- **最初から自前で書く。** 条件 3 のオートスクロールは、掴んでいる要素の祖先ではなく**ポインタが乗っているカラム**を、押したまま止めても滑らかに送り続ける必要がある。これを 3 つの webview で揃えるのは、Kanban を作る仕事ではない
- **条件 8 の確認を CI に載せる。** `tauri-driver` は macOS に無い（[0021](0021-two-layer-testing-for-the-webview.md)）。ここは手に残す

## 結果

得るもの。1〜7 が WebKitGTK で成立している。挿入位置の意味はこちらの関数にあり、Vitest で確かめられる。

引き受ける不都合。

- **更新の止まった依存を 1 つ抱える。** React の次の版で壊れたら、こちらで直すか自前に落とすかになる
- **条件 8 が未確認のまま残る。** macOS と Windows の実機で 1〜7 を確かめるまで、[0020](0020-pointer-based-drag-and-drop.md) の関門は閉じない
- **入れ子の並べ替えには、衝突判定を自分で絞る必要がある。** カラムの中にカードの並べ替えが入るので、素のままだとカラムを掴んだときにカードが落とし先に選ばれ、掴んでも何も起きない。`web/src/board/Board.tsx` の `collisionDetection` がそれを絞っている。dnd-kit を外しても、この絞り込みは要る
