# 0024. Linux で xdg-desktop-portal を必須にしない

- 日付: 2026-09-06
- 状態: 有効
- 関連: [0013](0013-linux-desktop-integration.md)、[0016](0016-where-the-app-says-things.md)、[0017](0017-moving-the-ui-to-tauri.md)

## 状況

gpui 版の Linux には、動かすのに `xdg-desktop-portal` が要った。README にこう書いてある。

> **Linux では xdg-desktop-portal も要ります。** 書き出し、データベースのコピー、データベースの場所を開く、テーマの「システムに合わせる」がこれを通ります。（中略）無くてもボードの操作はできますが、上の 4 つが動きません

gpui のファイル選択・場所を開く・外観の取得が、いずれもポータル越しだったためである。ポータル本体とデスクトップ環境に合ったバックエンドの**両方**を入れてもらう必要があり、入っていなければ 4 つの操作が黙って効かない。

Tauri へ移る段階 7 で、この 4 つを作り直した。**どれもポータルを通らなくなった。**

| 操作 | 移行後 |
| --- | --- |
| 書き出し・データベースのコピー（保存先を選ぶ） | `tauri-plugin-dialog`（既定の `gtk3` の口）。すでに WebKitGTK で GTK を積んでいるので、増える依存はない |
| データベース・バックアップの場所を開く | `tauri-plugin-opener`。D-Bus の `org.freedesktop.FileManager1` を先に試し、届かなければポータル、それも無ければ `xdg-open` |
| テーマの「システムに合わせる」 | CSS の `prefers-color-scheme`。webview が OS の設定を見る |

## 決定

**Linux でポータルを必須にしない。** `tauri-plugin-dialog` は既定の `gtk3` の口を使い、`xdg-portal` の feature は付けない。

README の「xdg-desktop-portal も要ります」を落とすのは、**配るものが Tauri のビルドに替わるとき**（`docs/TAURI-MIGRATION.md` の段階 9）である。いま配っている実行ファイルは gpui のもので、そちらはまだポータルを通る。書いてあることと配っているものを、先にずらさない。

## 理由

**要らなくなったから。** ポータルを必須と書いていたのは gpui の実装の都合で、ユーザーに約束したかったことではない。4 つのうち 3 つは、もうポータルを通っていない。

**入れてもらうものを増やさないため。** ポータルは本体とバックエンドの 2 つを揃えて初めて働き、揃っていないことは静かに（操作が効かない形で）表に出る。[0013](0013-linux-desktop-integration.md) が「ユーザーのディレクトリで完結させる」と決めた線と同じで、**動かすために管理者の手が要るものを増やさない。**

**GTK はすでに積んでいるから。** webview が WebKitGTK である以上、GTK のファイル選択は追加の依存にならない。`xdg-portal` の feature を選ぶと、そこだけがポータルを要求しはじめる。

## 採らなかった案

- **`tauri-plugin-dialog` の `xdg-portal` を選ぶ。** Flatpak のようなサンドボックスの中では portal が正解だが、ekanban はサンドボックスの中で配っていない（[0013](0013-linux-desktop-integration.md)、`.deb` と AppImage と `~/.local` への導線）。必須のものを 1 つ増やして得るものが無い
- **README をそのままにしておく。** 要らなくなった要求を書いたままにすると、入れなくてよいものを入れさせる。書いてあることが本当かどうか、読む人には確かめようがない
- **「場所を開く」も自分で `xdg-open` を叩く。** ファイル管理を選んで開くのは `tauri-plugin-opener` がすでにやっている。同じことを書き直しても、当たる環境が減るだけ

## 結果

得るもの。Linux で ekanban を動かすのに要るものが、glibc・WebKitGTK・GTK だけになる。ポータルが無い環境（軽量なウィンドウマネージャ、コンテナ）でも、書き出しとコピーが動く。

引き受ける不都合。

- **「場所を開く」だけは、まだデスクトップ環境しだい。** `FileManager1` を出すファイル管理も、ポータルも、`xdg-open` の設定も無い環境では何も起きない。**そこは黙る**（拒否は何も言わない、`docs/DESIGN.md`）ので、押した人には効かない理由が分からない
- **ファイル選択の見た目が GTK のものになる。** ポータル越しなら KDE では KDE の選択画面が出る。GTK の画面が出ることを、そのぶん受け入れる
