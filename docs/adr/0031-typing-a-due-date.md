# 0031. 期限は文字で打つ

- 日付: 2026-09-07
- 状態: 有効
- 関連: #134、#120、#128

## 状況

期限の欄は `<input type="date">` だった（#120）。日付選択のライブラリを足さずに
カレンダーを出せるので、3 つの webview で見た目と操作を確かめる対象が増えない、
という理由で選んだ形である。

使っていて次の 3 つが残った。

1. **キーボードから速く打てない。** 「来週の金曜」を入れたいとき、カレンダーを
   開いて数えるか、年・月・日の 3 セグメントを順に打つ必要がある。タイトルを
   打ってそのまま `Enter` で保存できる流れに、期限だけが乗っていない。
2. **webview ごとにカレンダーの見た目と操作が違う。** WKWebView・WebKitGTK・
   WebView2 で出るものが揃わないので、マニュアルで操作を一通りに説明できない。
   「対象を増やさない」ために選んだ形が、対象を 3 つ抱えていた。
3. #128 でパネルから「今日」「明日」などの近道ボタンを外したので、それを打てる
   道が要る。

## 決定

期限の欄を普通のテキスト欄にし、**打った文字の読み方は Rust に 1 つだけ置く**。

`ekanban_core::model::parse_due_date(value, today)` が次を受ける。基準日は引数で
受け、ここで時計を読まない。

| 打つもの | 読み |
| --- | --- |
| `2026-09-12` | そのまま |
| `9/12`、`9-12` | 今年。過ぎていれば来年 |
| `今日` `明日` `明後日` / `today` `tomorrow` | そのまま |
| `月`（`月曜`・`月曜日`）/ `mon` `monday` … | 次に来るその曜日。今日が同じ曜日なら 7 日後 |
| `+3` | 3 日後 |
| `来週` | 次の月曜 |
| `今週末` | 今日を含めて次に来る土曜 |

全角で打たれたものは、検索と同じ `normalize_search_text` で半角・小文字に均して
から読む。読めない文字列は今までどおり `InvalidDueDate` → `Validation` で欄の脇に
理由を返す。保存する形は `"YYYY-MM-DD"` のままで、データベースは何も変わらない。

打った文字がどう読まれたかは、欄の下に `→ 2026-09-12（土）` と出す。これは盤面を
変えない問い合わせコマンド `due_date_preview` で、`description_links` と同じ形の
口である。読めない間は何も出さない。

## 理由

**読み方を 2 か所に持たない。**「明日」が何日かを TypeScript でも数えると、
`due_statuses` を出した Rust の判定と食い違う日が来る。`docs/DESIGN.md`
「絞り込みと検索」が全角半角の正規化について言っているのと同じ理由で、
期限の読み方も Rust に 1 つだけ置く。往復するのは打った文字列と、読めた 1 日付だけ。

**確定する前に見せる。** 文字で受けると、打った人が思ったのと違う日に読まれうる。
`→ 2026-09-12（土）` を欄の下に出すのは、保存してカードを見に行かなくても
食い違いに気づけるようにするためである。曜日を Rust が付けるのは、
`toLocaleDateString` に任せると webview のロケール次第で言葉が変わるからである。

**`今週末` だけ今日を含める。** 今日が土曜なら今日が「今週末」である。曜日そのものを
打ったときは今日を含めない——`土` と打つ人は今日のことを言っていない。この 2 つは
語が違えば期待も違うので、揃えずに分ける。

## 採らなかった案

- **`type="date"` を残したまま、その隣に文字の欄を足す。** 同じ値を触る欄が 2 つ
  並ぶ。どちらが本物かを決める規則が要り、片方だけを直したときの振る舞いを
  説明できなくなる。
- **日付の解釈ライブラリ（chrono-english など）を足す。** 受けたいのは 7 つの形
  だけで、そのために依存を 1 つ増やす値打ちがない。日本語の語も自分で持つことに
  なるので、結局ここに同じ量のコードが残る。
- **読み方を TypeScript に置く。** 往復が減るように見えるが、判定が 2 つになる。
  年末年始や、`due_statuses` を出した日をまたいだときに食い違う。
- **読めない文字を打っている最中に赤く出す。** 打っている途中の文字は、まだ
  間違いではない。`9` と打った瞬間に断られる欄は打ちにくい。

## 結果

期限を打って `Enter` で保存できるようになり、カレンダーの見た目が webview ごとに
違う問題も消えた。引き受けた不都合は、**打った文字がどう読まれるかを覚える必要が
あること**である。`→` の行はそのために出しているが、それでも「`土` は今日を
含まない」のような細かい規則は、マニュアルを読まないと分からない。
