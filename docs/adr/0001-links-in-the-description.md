# 0001. 説明の URL を、説明欄の下に一覧で出す

- 日付: 2026-09-05
- 状態: 置き換えられた（→ [0002](0002-links-inside-the-description-field.md)）
- 関連: [#59](https://github.com/tokuhirom/ekanban/issues/59) [#70](https://github.com/tokuhirom/ekanban/pull/70)

## 状況

カードの説明はプレーンテキストで、URL を書いても押せなかった。開くには選択してコピーし、ブラウザに貼るしかない。issue、PR、設計文書へのリンクを説明に貼る使い方は多いので、負担のわりに効く改善だと見込んだ。

issue の案は「説明の中の URL の**その部分をリンクとして描く**」だった。しかし置ける場所が見つからなかった。

- 詳細パネルの説明は `Textarea` で、**読むだけの表示が無い**。文中をリンクにするには「フォーカスが無い間は描画テキスト、当たったら `Textarea` に差し替える」形になり、編集と IME の挙動に手が入る
- カードの表面の説明は切り詰められた予告で、そこでのクリックは「詳細を開く」に決まっている。押し先を足すと意味が増え、折り返しでカードの高さも変わる（D&D の安定が崩れる）

## 決定

文中は装飾せず、**詳細パネルの説明欄の下に、見つかった URL を一覧で並べる**。押すと `cx.open_url` で既定のブラウザが開く。

## 理由

受け入れ条件（押すと開く / 誤検出しない / 編集と保存の挙動が変わらない）を全部満たし、そのうえで `Textarea` に一切触らないので、編集・IME・保存の経路が完全に無傷になる。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 入力欄の文中をリンクにする | `Textarea` に読むだけの表示が無く、差し替える実装になる。編集と IME に手が入り、受け入れ条件と正面からぶつかる |
| カードの表面でリンクにする | クリックの意味が増える。折り返しでカードの高さが変わり、D&D の挿入位置の判定が不安定になる |

## 結果

URL に手が届くようにはなった。ただし、

- 説明のどこにあった URL なのかが分からない
- 説明と一覧で二重になり、パネルが縦に伸びる
- URL が 1 つでも見出しの行が増える

**この判断は 1 日で覆した。** 「入力欄には読むだけの表示が無い」で止めてしまい、`gpui-base` の入力欄が持つ口をそれ以上調べていなかった。実際には差し込む口があり、[0002](0002-links-inside-the-description-field.md) でそちらに移した。

教訓として残すなら、**「その部品にはできない」と結論するのは、その部品の公開 API を実際に読んでからにする**、ということ。
