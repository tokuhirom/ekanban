# 0044. タグの色を自動で割り振り、既定色をやめる

- 日付: 2026-09-08
- 状態: 有効
- 関連: [0027](0027-creating-tags-while-editing-a-card.md)（その「結果」に書いた不都合を引き取る）

## 状況

タグの色は、作るときに決まっていた。カード編集パネルから作ったタグには
`web/src/panel/tags.ts` の既定色（`#94a3b8`、灰色）が入り、タグ整理パネルには
色見本が 1 つ置いてあって、そこで選ばなければやはり同じ灰色が入った。

[0027](0027-creating-tags-while-editing-a-card.md) は、カードを書きながらタグを
作れるようにしたとき、この不都合を承知で引き受けている——「その場で作ったタグが
全部同じ既定色になることで、色で見分けたいなら結局タグ整理を開くことになる」。

**その「結局」が起きた。** タグを作る速い道ができたぶんタグは増え、増えた分だけ
盤面のチップは同じ灰色で並ぶ。カードの上でタグを見分けるものが名前しか無くなり、
色は、わざわざ塗りに行った人にしか働かない。塗りに行くのはタグが増えたあと、
つまり **1 つずつ塗るのがいちばん面倒になったころ**である。

色そのものは既に画面の役に立つ形で置かれている。チップは絞り込みの唯一の入口で
（`docs/DESIGN.md`「絞り込みと検索」）、カードの上に並ぶ。使われていないのは
「どの色にするか」を人が決めなければならない、その一点だった。

## 決定

**タグの色は自動で付ける。作るときに色を選ばせない。**

- `web/src/panel/tags.ts` に色の並び（`TAG_PALETTE`）を置き、**色を決めていない
  タグは、そのタグの ID からこの並びを引いて描く**。隣り合う ID が似た色に
  ならないよう、色相を飛ばして並べる
- 「色を決めていない」は、`Tag.color` が空文字であること。保存の形も TypeScript
  の型も変えない
- タグ整理パネルの「タグを追加」から色見本を外す。**作る道は 2 つとも名前だけに
  なる**。色を変えるのは、これまでどおりタグ整理パネルの一覧の側
- チップの文字色は、**そのチップの背景から決める**。濃いほうと淡いほうを当てて、
  コントラスト比の大きいほうを選ぶ
- 既に置いてあるタグのうち、**かつての既定色そのものが入っているものは「色を
  決めていない」に戻す**。SQLite は移行 13、ブラウザ版の JSON は
  `JsonStore::migrate`

`docs/DESIGN.md`「画面の作り」の 2 行を書き換える——色の直書きが許される場所の
説明と、[0027](0027-creating-tags-while-editing-a-card.md) が書いた「色は既定色で」
の行。

## 理由

**色を決める仕事が、色から値打ちを奪っていたから。** 見分けるための色に、
見分けたい人が 1 つずつ色を選ぶ手間が前置きされていた。タグが 3 つのうちは
やらなくても困らず、10 になったころには 10 回ぶんの手間になっている。自動で
付けば、どちらの時点でも既に付いている。

**ID から引くのは、色が動かないからである。** 「使われていない色から順に配る」
という決め方もあるが、それは配った時点の顔ぶれに依存する。タグを 1 つ消した日に
残りの色が入れ替わると、色で覚えていたものが役に立たなくなる。ID は増えるだけで
戻らないので、一度付いた色は動かない。パレットより多く作れば一巡するが、**色は
タグの識別子ではなく見分けるための手がかり**で、名前は常にチップに出ている
（`docs/DESIGN.md`「色だけに意味を持たせない」）。

**文字色を背景から決めるのは、色をユーザーが決められるからである。** 素の
`--color-foreground` のままだと、ライトテーマの濃い文字が濃いチップに沈み、
ダークテーマの淡い文字が淡いチップに溶ける。どちらも実際に選べる色で起きる。
明るさの境目を 1 つ決め打ちにすると境目の両側に読めない色が残るので、比が大きい
ほうを選ぶ。パレットのどの色でも 4.5:1 以上になることは `tags.test.ts` が数える。

**移行を書くのは、既定色が「選んだ色」ではないからである。** あれは色を決める
前の姿だった。戻さなければ、いままでのタグだけが灰色で残り、新しいものとの違いが
「いつ作ったか」でしか説明できない。**この変更が直したかったのは、まさにいま
灰色で並んでいる盤面**である。

## 採らなかった案

- **既定色を変えるだけにする。** 同じ色が並ぶことは変わらない。色数の問題では
  なく、色が 1 つしか無いことの問題である
- **名前から色を作る（ハッシュ）。** 名前を直したときに色が変わる。タグの名前は
  タグ整理パネルでいつでも直せるので、直した瞬間に見分けの手がかりが入れ替わる。
  ID なら動かない
- **作るときに色を選ばせたまま、既定だけを順送りにする。** タグ整理パネルの
  色見本は残せるが、カード編集パネルから作った道との差が残る。作る道が 2 つある
  以上、**どちらで作っても同じ結果になる**ほうが説明が短い
- **`Tag.color` を `Option<String>` にする。** 「決めていない」を型で表せるが、
  スキーマと生成した型と書き出しに手が入る。空文字で足りるものを、形を変えて
  まで区別する理由が無い
- **チップの文字色をテーマごとに切り替える。** チップの背景はライトでもダークでも
  同じ色なので（テーマで塗り替えると、同じタグが 2 つの顔を持つ）、切り替える先が
  無い。決まるのは背景からである
- **移行を書かず、いまあるタグはそのままにする。** 塗り直しはタグ整理パネルから
  できる。だが 1 つずつ塗る手間こそが、この変更が無くしたかったものである
- **かつての既定色を、読むたびに「決めていない」と読み替える。** 移行が要らなく
  なる代わりに、**その灰色だけは二度と選べない色になる**。過去の値の始末は、
  過去に 1 度だけ行うのが移行である

## 結果

タグは作った瞬間から見分けが付く。既にあるタグも、次に開いたときに色が付く。
色を選ぶ操作は、いままでどおりタグ整理パネルに残っている——**選ばなくてよく
なっただけで、選べなくなってはいない。**

引き受けた不都合は 3 つある。

- **自分で灰色（`#94a3b8`）を選んでいた人は、その指定を失う。** そのタグは自動の
  色に移る。色見本から選び直せる
- **一度でも色見本を動かすと、そのタグは自動の色に戻せない。** 戻す口を置くと、
  タグ 1 行あたりのボタンが増える（`docs/DESIGN.md`「常用しない操作を画面に常時
  出さない」）。直後なら Undo で戻る
- **パレットより多くタグを作ると、色が一巡して重なる。** 重なった 2 つは名前で
  見分けることになる
