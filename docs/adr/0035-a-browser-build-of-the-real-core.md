# 0035. ブラウザで試せる版は、中核を wasm に組み直して作る

- 日付: 2026-09-07
- 状態: 置き換えられた（→ [0042](0042-the-browser-build-is-the-same-typescript.md)）
- 関連: [0018](0018-rust-owns-the-board-state.md)、[0021](0021-two-layer-testing-for-the-webview.md)、[0036](0036-one-model-two-places-to-put-it.md)

## 状況

このアプリは、入れて起動しないと触れない。macOS の配布物は署名も公証もしていないので、**初回だけ手順が要る**（[0014](0014-unsigned-apple-silicon-only-macos-builds.md)）。「ドラッグの気持ちよさがいちばん大事」と言っているものを、いちばん確かめにくい形でしか置いていない。

手元での確認も同じで、`make dev` は Rust のツールチェーンと WebKitGTK の開発パッケージが揃ってはじめて動く。画面だけ見たい人にも、それが要る。

**リンクを 1 つ渡せば触れる版が要る。** 盤面は、開いた人のブラウザの中だけに残ればよい——サーバーを持たないことは「やらないこと」に書いてあり、それは変えない。

決めるのは、**その版のバックエンドをどう用意するか**である。

## 決定

**`crates/core` と `crates/app` のコマンドを `wasm32-unknown-unknown` に組み直し、ブラウザの中で動かす。** 盤面は `localStorage` に置く（置き方は [0036](0036-one-model-two-places-to-put-it.md)）。

- `crates/web`（`ekanban-web`）が新しく入る。**ここに入るのは環境の差だけ**——保存先、ファイルの持ち出し方、URL の開き方。盤面に関わる判断は 1 つも書かない
- `crates/app` に `shell` feature（既定で有効）を足し、Tauri を知っているもの（`ipc` / `run` / `window` / `capture` / `shortcut` の登録・`menu` の変換）をその内側に置く。外側に残るのは `commands` / `dispatch` / `state` / `snapshot` / `error` と、**メニューの「データとしての構成」**
- コマンド名で振り分ける表を `crates/app/src/dispatch.rs` に出し、開発用のハーネスとブラウザ版が**同じ表**を通る
- メニューバーはページが描く。**構成は Rust が返す**（`menu::web_sections`）
- `crates/core` から `std::time::SystemTime` を外し、chrono に替える。`wasm32-unknown-unknown` には `SystemTime` の実装が無く、呼ぶとパニックする
- 置き場所は GitHub Pages。`main` に入るたびに組み直す

## 理由

**偽物のバックエンドを書かないため。** [0021](0021-two-layer-testing-for-the-webview.md) が「TypeScript で書いた偽物は必ず本物からずれる」と決めており、その決定はテストのためだけのものではない。**ブラウザで動く版を偽物で作れば、いちばん多くの人が触るのが偽物になる。** ずれた日、直したはずの不具合がデモにだけ残り、直っていない不具合がデモにだけ無い。ここで本物を動かせば、ずれようがない。

**答えているものが本物だと、確認に使える。** ドラッグの落ち先を決めているのは `board/dnd.ts` と `model.rs` で、期限の読み方も検索の正規化も Rust にある。ブラウザ版で試した動きは、アプリで起きる動きである。「デモではこうなるが実物は違う」と断らずに済む。

**組み直せることが分かったため。** `model.rs` も `commands.rs` も、時刻の取り方（`SystemTime` は wasm に実装が無い）を直しただけで動いた。置き場所だけは差し替えることになったが、それは大きさの話で、[0036](0036-one-model-two-places-to-put-it.md) にある。

**表を 1 つにできるため。** ハーネスは `crates/app` のコマンドを HTTP に出しており、ブラウザ版は同じものを wasm の呼び出しに出す。運び方が違うだけなので、振り分けの表を共有すれば、**片方にだけコマンドが増えた日**が来ない。

**メニューを 2 か所に書かないため。** `menu.rs` は「先にデータとして組み、あとで Tauri のメニューに変換する」形になっている（[0015](0015-a-menu-bar-on-every-platform.md)）。ブラウザには変換先が無いだけで、組んだデータはそのまま使える。ページが描くのは、そのデータから **OS が持っているものを落としただけ**のものである。

## 採らなかった案

- **`invoke` を TypeScript の偽物で差し替える。** いちばん速い。[0021](0021-two-layer-testing-for-the-webview.md) が採らなかった案そのもので、理由もそのまま当てはまる。**本物に追従させ続ける仕事が増え、それは 2 つ目の実装を持つのと変わらない**
- **`ekanban-harness` を公開のサーバーに置く。** ブラウザだけで完結する。ただしサーバーを持つことになり、「アカウント・サーバー通信を持たない」という約束と、置いた人が他人の盤面を預かる形とが、どちらも崩れる。ハーネスは認証も暗号化も持たない開発用のもので、配るものではない
- **動画と画像だけ置く。** 費用がいちばん低い。**触れないので、いちばん大事にしているもの（ドラッグの手ざわり）が伝わらない**
- **`localStorage` ではなく OPFS / IndexedDB に置く。** OPFS は専用ワーカーの中でしか使えず、IndexedDB は非同期なので、コマンドの経路（同期で開いて同期で書く）を全部作り直すことになる。**試してもらうための版に、そこまでの器は要らない**——数 MB で足りる。足りなくなったときは、そのとき移す

## 結果

得るもの。リンク 1 つで触れる版ができ、**そこで動いているのが本物のモデル**である。副産物として、コマンドの層が Tauri から切り離されていることが、feature の形で確かめられるようになった（`cargo build -p ekanban-app --no-default-features`）。

引き受ける不都合。

- **配るアプリと違うところが残る。** クイックキャプチャ（ページの外まで届く割り当てが作れない）、ファイル管理で場所を開くこと、ウィンドウの操作。どれも**消さずに灰色にし、理由を文言に入れる**
- **どの OS で開かれたかを、ページが名乗る。** `wasm32-unknown-unknown` は macOS でも Linux でもないので、`Platform::current()` に訊いてもキーの割り当てを決められない。**配るアプリの経路は変えない**——あちらは今までどおり Rust がコンパイル時に知っている（[0009](0009-per-platform-key-bindings.md)）
- **メニューの割り当てが全部は効かない。** `Ctrl+N`・`Ctrl+T`・`Ctrl+W` は多くのブラウザが自分で取る。止める手立てがないので、その項目はメニューから押してもらう
- **wasm を 1 つ落とすことになる。** 初回だけで、大きさは [0036](0036-one-model-two-places-to-put-it.md) にある
- **`localStorage` は数 MB で埋まる。** 埋まったら書けなくなるので、**黙って飲み込まずにその場で伝える**——次に開いたときに変更が消えている、が起きないようにする
- **クイックキャプチャと、ファイル管理で場所を開くことに加えて、データベースの控えも使えない**（[0036](0036-one-model-two-places-to-put-it.md)）。盤面の持ち出し（JSON と Markdown）は残る
- **組み立てが 1 つ増える。** `wasm-pack` が要り、CI のジョブも 1 つ増える。pull request でも組んで e2e まで走らせる——`main` に入ってから壊れていたことを知るのでは遅い
