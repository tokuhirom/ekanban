# 0014. macOS は Apple Silicon 向けの未公証ビルドだけを配る

- 日付: 2026-09-05
- 状態: 有効
- 関連: #55

## 状況

macOS の配布について 3 つのことが同時に問題になった。

1. **README の初回起動の手順が、いまの macOS では通らない。** 「初回は右クリックから『開く』を選んでください」と案内していたが、macOS 15 (Sequoia) 以降この Control クリックでの回避は塞がれていて、署名・公証されていないアプリは「システム設定 > プライバシーとセキュリティ」から明示的に許可する必要がある。手順どおりにやっても開けない人が出る
2. **Apple Silicon だけ。** `.github/workflows/release.yml` の matrix は `aarch64-apple-darwin` のみで、Intel Mac 向けも Universal も出していない
3. **ad-hoc 署名のまま。** `script/bundle-mac` は `CODESIGN_IDENTITY` が空だと ad-hoc（`-`）に落ちる。Developer ID を渡せば hardened runtime とタイムスタンプは付くが、公証（`notarytool submit` → `stapler staple`）はワークフローに入っていない

1 は誤った案内なので直す。2 と 3 は「やる / やらない」を決める必要があった。

## 決定

**1 だけ直す。** README と `docs/DEVELOPMENT.md` の初回起動の案内を、macOS のバージョンごとに書き分ける。

**2（Intel / Universal）はやらない。** Apple Silicon 向けだけを配り続ける。

**3（Developer ID での署名と公証）はやらない。** ad-hoc 署名のままにする。

2 と 3 は、どちらも「要るようになったら」ではなく、**いまは要らないと判断した**ものとして `docs/DESIGN.md` に残す。

## 理由

**誤った案内は、無い案内より悪い。** 手順どおりにやって開けなかった人は、自分の環境か、アプリのほうが壊れていると考える。実際にはどちらでもない。これは費用も判断も要らず、直さない理由がない。

**Intel をやらないのは、確かめる手段が無いから。** ビルドを足すだけなら難しくない（`macos-15-intel` のジョブか `lipo`）が、動かせる Intel Mac が手元に無い。GPU を使う（gpui は Metal を通る）アプリで、実機で一度も起動していないバイナリを「対応」として配るのは、README に「ビルドが通ることしか確かめていません」と書いてある Windows と同じ状態を 1 つ増やすことになる。Rosetta は arm64 バイナリを Intel で動かす仕組みではないので、逃げ道にもならない。

**公証をやらないのは、年額の登録が要るから。** Apple Developer Program の費用は、単独ユーザー向けのローカルアプリで、ソースが公開されていて自分でビルドできるものに対して、いま払う理由が見つからない。払えば初回起動の手順そのものが消えるので、そこは分かったうえで引き受ける。**手順を正しく書く**ことが、それをやらない側の責任にあたる。

**判断を「保留」として書かない。** 「必要になったら」と書いた項目は読み返されない。いまは要らないと決めた理由を書いておけば、次に同じ話が出たときに、その理由がまだ成り立つかだけを見ればよくなる。

## 採らなかった案

- **Intel 向けのビルドだけ足して「未検証」と断る。** 動くかどうか分からないものを配ると、動かなかったときの問い合わせに答えられない。断り書きは、動かない体験の埋め合わせにならない。
- **`lipo` で universal binary にする。** 成果物が 1 つで済むのは利点だが、確かめられない半分を含むことは変わらない。ダウンロードの大きさが倍近くになる分、Apple Silicon の人が損をする。
- **公証だけ入れて署名は ad-hoc のまま。** できない。公証には Developer ID での署名が前提。
- **Homebrew Cask で配る。** cask 自体は署名の要否を変えない。`--no-quarantine` を要求する cask になり、初回の手順が別の形で残るだけ。配布経路を 1 つ増やす手間に見合わない。
- **アプリ内で「Gatekeeper に止められたら…」と案内する。** 止められている間はアプリが起動していないので、出す場所が無い。

## 結果

初回起動の案内が、いまの macOS で通るようになった。

引き受けたのは、Intel Mac では使えないことと、初回に手順が要ること。どちらも README に書いた。ソースからのビルドは全プラットフォームで通る（CI が macOS / Linux / Windows で回している）ので、どうしても要る人にはその道が残っている。

この判断は費用と手元の機材で決めている。Developer Program に登録する理由が別にできたときや、Intel Mac が手元に来たときには、覆してよい。
