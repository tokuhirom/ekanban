# 0033. 説明は Markdown のエディタで書く

- 日付: 2026-09-07
- 状態: 有効
- 関連: #129、[0002](0002-links-inside-the-description-field.md)（置き換え）

## 状況

説明はプレーンテキストで、`textarea` の裏に同じ字送りの表示層を重ね、そこで
URL にだけ色と下線を付けていた（[ADR 0002](0002-links-inside-the-description-field.md)）。
URL を見つけるのは Rust の `description_links` で、webview が受け取るのは位置の
配列だけだった。`docs/DESIGN.md`「やらないこと」には Markdown の描画が入っていた。

使っていて出たのは「中途半端に自前のもので、体験が悪い」だった（#129）。実際、
この作りは次を抱えていた。

- **層を 2 枚重ねているので、ずれると本文が消えたように見える。** 入力欄に下地を
  塗ってはいけない、変換中は層を入れ替える、といった注意が CSS とテストに散っている
- **書けるのは素の文章だけ。** 手順を箇条書きにも、語を強調にもできない
- URL の位置を打鍵のたびに Rust へ聞きに行っていた

## 決定

**説明の欄を Markdown のエディタにする。** 編集器は [Lexical](https://lexical.dev/)
（Meta、MIT）で、`@lexical/markdown` が読み書きを担う。

- **保存する形は Markdown の文字列**。`Card.description` の型もデータベースも
  書き出しも変わらない。編集器の中の木は表示のためだけのもので、出入りするときに
  文字列へ直す
- 打ちながら整う。`**太字**` `*斜体*` `` `コード` `` `# 見出し` `- 箇条書き`
  `> 引用`（`@lexical/markdown` の標準の変換）
- URL は打った瞬間にリンクになる。**開くのは修飾キー＋クリックのまま**
  （macOS は `Cmd`、ほかは `Ctrl`）
- 裏の表示層と `description_links` は消す。URL を拾う規則は
  `web/src/panel/links.ts` に移す
- `docs/DESIGN.md`「やらないこと」から「Markdown レンダリング」を外し、README の
  同じ行も直す

## 理由

**「どこがリンクか」は、エディタでは内部の状態そのものである。** 位置の配列を外から
受け取って色を塗る形は、`textarea` の上に層を重ねているから成り立っていた。編集器が
文書の木を持つなら、リンクはその木の節であり、外から位置で塗り直す作りには戻せない。
`docs/DESIGN.md`「判定は Rust に残す」は検索の正規化と期限の読み方には効いたままだが、
**この 1 つだけは編集器の側に移る**。

**開いてよい形かどうかは Rust に残す。** 説明はユーザーが打った文字列で、`file://` や
`javascript:` を混ぜられる場所である。`commands::openable_url` の判定は動かさない。
ここで移したのは「どこからどこまでが URL か」だけで、「開いてよいか」ではない。

**素のクリックでは開かない。** エディタの中では、クリックは「そこにカーソルを置く」
操作である。ADR 0002 が修飾キーを要求した理由はそのまま生きている。

**依存を 1 つ増やすことを引き受ける。** issue で「依存が増えることは問題ではない」と
決まった。Lexical を選んだのは、Markdown の読み書きとリンクが**公式パッケージ**に
あること、React 19 に対応していること、IME を前提に作られていること（Meta が日本語を
含む環境で使っている）の 3 つによる。

## 採らなかった案

- **Tiptap / ProseMirror.** Markdown の直列化が第三者パッケージ（`tiptap-markdown`）
  で、積み上がる依存も大きい。
- **Milkdown / Crepe.** 目的（`**` と URL が効く程度）に対して大きすぎる。
- **CodeMirror で記法を色づけする.** 記法が見えたままの編集器で、WYSIWYG ではない。
  issue の求めているものと違う。
- **表示だけ Markdown にする**（`textarea` の裏の層を広げる）。依存は増えないが、
  層を 2 枚重ねる作りそのものが残る。#129 が「中途半端」と言っているのはそこである。
- **保存形式を JSON（編集器の内部表現）にする.** 書き出し（Markdown / JSON）と
  検索がそのままでは動かなくなる。テキストで持つ値打ちのほうが大きい。

## 結果

説明に見出しと箇条書きと強調が書けるようになり、URL は打った瞬間にリンクになった。
CSS から層の重ね合わせが消え、打鍵ごとの IPC も無くなった。

引き受けた不都合は 2 つある。1 つは**依存が増えたこと**（Lexical とその周辺）。
もう 1 つは、**既存の説明が Markdown として読み直される**ことで、改行 1 つで区切って
いた段落は、次に保存したときに空行 1 つ（`\n\n`）に揃う。文字が消えることはないが、
ファイルの中身は変わる。段落の中で改行したいときは `Shift+Enter` を使う。
