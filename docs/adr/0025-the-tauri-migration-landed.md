# 0025. Tauri 移行の着地と、移行の設計文書を消すこと

- 日付: 2026-09-06
- 状態: 有効
- 関連: [0017](0017-moving-the-ui-to-tauri.md)、[0018](0018-rust-owns-the-board-state.md)、[0019](0019-typescript-react-vite-for-the-webview.md)、[0020](0020-pointer-based-drag-and-drop.md)、[0021](0021-two-layer-testing-for-the-webview.md)、[0022](0022-dnd-kit-core-for-drag-and-drop.md)、[0023](0023-verifying-the-webview-engines.md)、[0024](0024-no-portal-requirement-on-linux.md)

## 状況

[0017](0017-moving-the-ui-to-tauri.md) で UI を gpui-kit から Tauri へ移すと決め、何をどう作り直すかを `docs/TAURI-MIGRATION.md` に書いた。その文書は冒頭にこう書いていた。

> **この文書は移行が着地するまでの地図です。** 着地したら消します。そのとき、守るべき規則は `docs/DESIGN.md` へ、判断の経緯は ADR へ移り、ここには何も残りません。

段階 1 から 10 まで通り、gpui のクレートは消えた。地図は目的地に着いた。

**地図を残すと、規則の置き場所が 2 つになる。** `docs/DESIGN.md` は「いま従うべき規則」の一覧だと自分で名乗っている。移行の設計文書にも「これからこうする」という形で同じ規則が書かれているので、両方が残れば、どちらを読めばよいかを毎回判断させることになる。片方だけを直した日に、2 つは黙って食い違いはじめる。

## 決定

**`docs/TAURI-MIGRATION.md` を消し、そこにあった規則を `docs/DESIGN.md` へ移す。**

- 移した規則は「これからこうする」ではなく「こうなっている」の形に直す。層の分け方、状態の持ち主、コマンドとイベント、境界を越える値、画面の作り、D&D、メニューとキー割り当て、ウィンドウ、クイックキャプチャ、アプリが伝えること、テスト、ビルドと配布
- `docs/DESIGN.md` の gpui 由来の行は、移行の設計文書の §14 が予告したとおりに書き換える。**判断の中身は残し、実装の話だけを落とす**
- ソースのコメントが指していた `docs/TAURI-MIGRATION.md` §N は、`docs/DESIGN.md` の対応する見出しに向け直す。そのために `docs/DESIGN.md` の規則を見出しで区切る
- **移行の経緯そのものは ADR に残る。** 0017 から 0024 までの 8 本と、この 0025 で、なぜ移ったか・何を選んだか・何を確かめたかは読める。消えるのは「これから何をどの順で作るか」という、もう答えの出た問いだけ

## 理由

**規則の置き場所を 1 つにするため。** 上のとおり。

**段階ごとの計画は、終わった時点で誤りになるため。** 移行の設計文書には「段階 4 で spike する」「段階 9 で配る」のような、実行の順序が書いてある。全部終わったあとにそれを読むと、これからやることのように読める。終わった計画は履歴であって、規則ではない。

**書いてあることと、実際にやったことが違う箇所があるため。** 地図は先に書くので、実装が答えを返してくると外れる。外れた地図を残すと、次に来た人はそれを規則として読む。実際に外れたのは次の 3 つで、どれも `docs/DESIGN.md` には**実装のほう**を書いた。

| 地図が書いていたこと | 実際 |
| --- | --- |
| デスクトップエントリの `StartupWMClass` は `identifier`（`dev.tokuhirom.ekanban`）と合わせる | tao が名乗る `WM_CLASS` は**実行ファイルの名前**から作られる（`ekanban`）。`crates/core` に `WM_CLASS` の定数を置き、エントリと突き合わせるテストをそちらに向けた |
| クイックキャプチャの割り当ての保存形式が Tauri の表記に変わるので、スキーマ v11 で 1 回だけ変換する | 保存形式を**変えなかった**。`crates/app/src/shortcut.rs` が両方向に変換する。移行を書けば、読めなかった割り当ては黙って消える。変換のほうを持てば何も消えない |
| 殻の確認は `tauri-driver` の煙テストで行う | [0023](0023-verifying-the-webview-engines.md) が置き換えた。エンジンの系統（Chromium と WebKit）で Playwright を回し、本物のウィンドウは Xvfb 上で手で確かめる |

**予告どおりに消えたものもある。** 「ボードは開いた時点でフォーカスを持つ」は、メニューが `app:action` を投げてフロントの dispatcher が受ける形になり、フォーカスに関係なく届くので要らなくなった（#92 #93 が閉じた理由でもある）。「新しいカードは保存されるまで足さない」は、下書きが webview のものになって**経路ごと消えた**——規則の意図（無題のカードを作らない、取り下げを履歴に残さない）は、経路が無いことでそのまま満たされる。

## 採らなかった案

- **移行の設計文書を「歴史」として残す。** 残せば読まれ、読まれれば規則として扱われる。日付を打って「これは過去の計画です」と書き足す手もあるが、それを守り続ける仕組みがない。git の履歴には残るので、本当に読みたい人は読める
- **`docs/DESIGN.md` を分割し、移行後の規則を別の文書にする。** 規則が 2 つの文書に分かれるのは、いま消そうとしている状態そのもの
- **規則を移さず、ソースのコメントに散らす。** コメントは変更に追随しやすいが、一覧できない。「いま従うべき規則」を通しで読める場所が要るというのが、`docs/DESIGN.md` がある理由
